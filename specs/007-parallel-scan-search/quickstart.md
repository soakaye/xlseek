# Quickstart & Verification Guide: 並行ファイル走査・即時検索パイプライン (007-parallel-scan-search)

本ドキュメントは、ディレクトリスキャンとファイル内容検索のパイプライン並行化、およびキャンセル即時応答化の検証手順とテストシナリオを定義する。

---

## 1. 前提条件と環境準備

- Node.js 18+ および npm
- Rust 1.75+ (edition 2021)
- 作業ディレクトリ: リポジトリルート (`exlgrep`)

---

## 2. 自動テストおよび品質ゲート検証

### 2.1 バックエンド単体テスト
ディレクトリスキャンの中断、パイプライン並行処理、および既存機能が全て正常動作することを検証する。

```bash
cd src-tauri
cargo test
```
**期待される結果**:
- `test_collect_files_cancellation`（新規テスト: スキャン中の即時中断）がパスすること。
- `test_search_engine_parallel_pipeline`（新規テスト: スキャンと検索の並行動作）がパスすること。
- 既存のすべての単体テスト（8件以上）が 1 件のエラーもなくパスすること。

### 2.2 バックエンドコード品質 (Clippy & Format)
```bash
cd src-tauri
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```
**期待される結果**: 警告およびフォーマット差異が 0 件であること。

### 2.3 フロントエンド型チェック & ビルド
```bash
npm run build
```
**期待される結果**: TypeScript 型エラー（`tsc`）が 0 件で exit code 0 で Vite ビルドが完了すること。

## 3. 手動動作検証シナリオ

### シナリオ 1: 大規模ディレクトリでの初回結果表示の即時化 (TTFR)
1. アプリを起動する（`npm run tauri dev` または開発ビルド）。
2. サブフォルダ多数、かつ数十個以上のExcelファイルを含むディレクトリを指定する。
3. 任意の検索キーワード（例: `Total` や `売上`）を入力し、「検索開始」をクリックする。
4. **検証項目**:
   - ディレクトリ全体の走査完了を待つことなく、最初の数ファイルが読み込まれた段階で直ちに検索結果テーブルにセル情報が表示され始めること。
   - ステータスバーに「検出・走査中 (N ファイル)」とパルスアニメーションが表示され、スキャン完了後に確定パーセンテージバーにスムーズに遷移すること。

### シナリオ 2: ディレクトリ走査中の即時キャンセル (Fast Cancellation)
1. 階層の深い大規模フォルダを対象に検索を開始する。
2. 検索開始直後（1秒以内、ファイル検出が進行中）に「中止（キャンセル）」ボタンをクリックする。
3. **検証項目**:
   - 1秒未満で即座に走査が停止し、ステータスバーが「検索を中断しました」に切り替わること。
   - アプリケーションがフリーズせず、直ちに別の検索キーワードの入力や再検索が可能であること。
   - 中断時点でヒットしていた結果があれば、テーブル上にそのまま保持されていること。

### シナリオ 3: 空フォルダまたは対象ファイルが存在しない場合
1. Excelファイルが存在しないフォルダを指定して検索を実行する。
2. **検証項目**:
   - 余計な待機時間なく即座に完了し、「完了: 0 件一致 (0 ファイル走査)」が表示されること。
