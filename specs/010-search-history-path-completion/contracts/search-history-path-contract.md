# Contract: 検索履歴とパス補完

## 画面契約

- 検索テキスト欄と検索ディレクトリ欄には、それぞれ履歴を開く専用ボタンを置く。履歴は新しい順に表示し、選択は対応する入力欄だけを変更する。
- ディレクトリ欄への入力中は補完候補を表示する。履歴ボタンを押したときは補完候補を閉じて履歴を表示する。履歴が空なら空状態を案内する。
- 履歴と補完のリストはキーボードで開閉・移動・確定できる。IME の変換中はリスト確定や検索を行わない。選択は検索を開始しない。
- 設定画面は保存件数を 0～50 の整数で受け付ける。無効値は確定させず範囲を示す。0 を選ぶと両履歴を消去する。
- 追加文言は既存の日英翻訳資源から表示する。保存失敗は通知するが、現在の検索操作を止めない。

## 検索開始 IPC

既存の `start_search(query: SearchQuery)` を維持する。受付前に必須入力、ディレクトリの実在・読取可否、正規表現検索時のパターンの妥当性を確認し、`~/`（Windows では `~\` も）は利用者のホームディレクトリへ解決する。読取確認はブロッキング用スレッドで行い、`read_dir` の結果から不存在と権限拒否を区別する。受付できない場合は既存の `PathNotFound`、`PermissionDenied`、`InvalidRegex`、`SearchFailed` のうち該当する構造化エラーを返し、検索処理を起動しない。成功応答を返した後、画面は元の `keyword` と `target_dir` を履歴に保存する。受付後の検索エラーや中断では履歴を取り消さない。

## 補完 IPC

`complete_directory_path(path_input: string) -> string[]` を追加する。OS に応じた絶対パスとホーム省略表記を受け、入力済みの親直下から末尾名に前方一致するディレクトリの表示用パスを、整列後に一定件数以内返す。末尾が区切り文字ならそのディレクトリを親として空の接頭辞で列挙する。通常ファイルは除く。親が存在しない・読めない・対象外の入力なら空配列を返す。列挙はブロッキング用スレッドで実行し、内部エラーでも入力欄の値は変えない。呼出し側は連続入力時の古い応答を破棄する。

### Windows パス

- Windows ではドライブ付き絶対パス（`C:\Reports\`、`C:/Reports/`）と UNC 共有パス（`\\server\share\Reports\`）を補完対象とする。区切り文字の判定は Windows のパス規則に従う。`C:Reports`、`\Reports`、通常の相対パスは現在位置に依存するため補完しない。
- ホームディレクトリの省略表記は Windows では `~/` と `~\` の両方を受ける。候補を選ぶまでは元の入力を変えず、履歴には入力欄で使用した表記を保存する。選択した候補は検索可能なパスを返し、ホーム省略表記の接頭辞は維持する。
- UNC の共有先が未指定・未接続・読取不可なら候補は空配列とし、入力欄を変更しない。検索開始時の実在・読取検証は通常の構造化エラーを返す。`\\.\` のデバイスパスと `\\?\` の拡張長パスは補完対象外とし、Windows のパス接頭辞の種類で判定する。

## 保存値契約

端末内の単一キーに [data-model.md](../data-model.md) の 3 項目を保存する。保存値は読み込み時に型・範囲・重複・上限を検証する。無効な保存値は初期状態で扱い、画面の起動と検索を妨げない。
