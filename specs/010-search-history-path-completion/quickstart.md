# Quickstart: 検索履歴とディレクトリ補完の検証

## 準備

アプリを起動し、検索できるフォルダを 2 つ用意する。一方の親フォルダには、名前の接頭辞が共通する複数のサブフォルダ、通常ファイル、空白と日本語を含むフォルダを置く。ホームディレクトリの下にも補完を試せるフォルダを用意する。既存の言語設定を日本語・英語の両方で確認できるようにする。

## 自動検証

```text
npm test
npm run lint
npm run build
cd src-tauri
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

各コマンドが終了コード 0 で完了し、Clippy と ESLint の警告がないことを確認する。Rust テストはパス解決・親直下の候補・不正パス、画面テストは履歴の重複排除・件数変更・保存失敗・リスト操作を対象にする。

## デスクトップでの確認

1. 異なる検索テキストとディレクトリで検索を開始する。両欄の履歴ボタンから新しい順の値を選べ、選択だけでは検索が始まらないことを確認する。結果ゼロ件と開始後の中断も履歴に残る。
2. 存在しないディレクトリ、および不正な正規表現で検索を試みる。検索が始まらず、エラーが示され、どちらの履歴にも追加されないことを確認する。
3. アプリを再起動し、両履歴が保持されることを確認する。保存件数が 0～50 の整数であることを確認する。設定画面で件数を 2 に下げ、両履歴がそれぞれ 2 件以内になることを確認する。50 は受け付け、51 と整数以外は拒否する。さらに 0 にして両履歴が消え、再起動後も戻らないことを確認する。
4. 絶対パスと `~/` の途中まで入力する。親直下の一致するフォルダだけが表示され、通常ファイルと相対パスからは候補が出ないことを確認する。末尾に区切り文字を入力した場合は、そのディレクトリ直下の候補が表示されることを確認する。候補選択後のパスで検索できることを確認する。
5. ディレクトリ入力中に履歴ボタンを押し、補完から履歴へ表示が切り替わることを確認する。マウスを使わずに両リストを操作する。日本語入力の変換確定で候補選択や検索が誤発火しないことを確認する。
6. 日本語と英語の表示に切り替え、履歴・補完・保存件数の案内が切り替わることを確認する。端末内保存を失敗させた場合も検索は続けられ、失敗が通知されることを確認する。
7. Windows では `C:\Reports\`、`C:/Reports/` と `\\server\share\Reports\` の候補が選択後に検索できることを確認する。`~\` からの候補と検索も確認する。`C:Reports`、`\Reports`、デバイスパス、拡張長パスには候補が出ず、未接続の共有先では入力値が保持されることを確認する。

操作の期待結果と値の条件は [契約](contracts/search-history-path-contract.md) と [データモデル](data-model.md) を参照する。
