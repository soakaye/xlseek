# Data Model: 検索履歴とディレクトリ補完

## 保存する検索履歴

1 つの端末内保存値に、次の 3 項目を置く。

| 項目 | 型 | 条件 |
|---|---|---|
| `maxEntries` | 整数 | 0～50。保存値がない場合は 20 |
| `keywords` | 文字列配列 | 検索テキスト。重複なし、新しい順、長さは `maxEntries` 以下 |
| `directories` | 文字列配列 | 入力欄のパス表記。重複なし、新しい順、長さは `maxEntries` 以下 |

検索テキストとパスは個別の項目として扱い、検索時の組み合わせやその他の検索オプションは保存しない。空白のみの値は追加しない。重複は文字列の完全一致で判定し、再利用した値は先頭へ移す。ホーム省略表記は実パスへ置換せず保存する。

## 状態遷移

| 操作 | 変化 |
|---|---|
| 初回起動・無効な保存値 | `maxEntries=20`、両配列は空 |
| 検索開始成功 | 両配列の対象値を先頭へ移し、上限を超えた末尾を削る |
| 検索開始失敗 | 履歴は変更しない |
| 保存件数の変更 | 0～50 の整数を反映し、両配列を直ちに上限で切る。0 なら空にする |
| 履歴の選択 | 対応する入力欄だけを更新し、履歴の順序と検索状態は変更しない |
| 端末内保存の失敗 | 画面内の状態と検索は利用できる。保存失敗を通知する |

## 補完候補

補完候補は保存しない。入力欄のパスから親ディレクトリと末尾の名前を取り出し、親直下のディレクトリで前方一致する項目を表示用パスとして返す。末尾が区切り文字なら入力したディレクトリを親とし、空の接頭辞で直下の候補を返す。絶対パスでは絶対表記、ホーム省略表記ではその接頭辞を保つ。相対パス、存在しない親、読めない親では空配列を返す。入力が変わった後に届いた古い応答は表示しない。

Windows のドライブ付き絶対パスと UNC 共有パスは OS のパス規則で分割する。`~\` もホーム省略表記とし、その接頭辞を候補で維持する。ドライブ相対・ルート相対・デバイス・拡張長パスは補完対象外とする。履歴では区切り文字や大文字・小文字を含む元の入力表記を維持する。
