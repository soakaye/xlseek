# Feature Specification: 検索履歴とディレクトリ補完

**Feature Branch**: `010-search-history-path-completion`

**Created**: 2026-09-27

**Status**: Draft

**Input**: User description: "検索テキスト・検索ディレクトリの履歴を保存。履歴はドロップダウンリストから選択可能とする。保存履歴数は、設定画面から設定可能。検索ディレクトリの入力はパス名補完を持つ。"

## Clarifications

### Session 2026-09-27

- Q: 検索履歴には、どの時点の条件を保存しますか？ → A: 必須入力と検索可能なディレクトリを確認して検索を開始した時点。結果ゼロ件、中断、開始後の失敗でも履歴に残す。
- Q: 検索ディレクトリ欄では、履歴とパス補完の候補をどのように表示しますか？ → A: 履歴は専用ボタンから開き、入力中は補完候補を表示する。
- Q: パス補完は、どの形式の入力に対応しますか？ → A: 絶対パスとホームディレクトリを表す `~/` に対応する。相対パスは補完対象外とする。
- Q: 保存件数と Windows パスはどう扱いますか？ → A: 保存件数は 0～50 の整数。Windows ではドライブ付き絶対パスと UNC 共有パス、ホーム省略表記の `~/`・`~\` を補完する。現在位置に依存するパスは補完しない。
- Q: 正規表現検索でパターンが不正な場合、その入力を検索履歴に保存しますか？ → A: 保存しない。検索開始前にエラーを示す。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 過去の検索条件を再利用する (Priority: P1)

利用者は検索テキストと検索ディレクトリそれぞれの入力欄で履歴を開き、過去に使った値を選択して再利用できる。履歴はアプリの再起動後も残る。

**Why this priority**: 繰り返し検索する際の入力を減らす、機能の中心となる操作である。

**Independent Test**: 異なる条件で検索し、両入力欄の履歴から値を選択した後、アプリを再起動して同じ値を選択できることを確認する。

**Acceptance Scenarios**:

1. **Given** 必須入力と検索可能なディレクトリが指定されている、**When** 検索が開始される、**Then** 検索テキストと検索ディレクトリがそれぞれの履歴の先頭に保存される。
2. **Given** それぞれの履歴が存在する、**When** 対応する入力欄のドロップダウンリストから項目を選ぶ、**Then** その入力欄だけが選択値に置き換わり、検索は自動実行されない。
3. **Given** 検索ディレクトリを入力している、**When** 履歴ボタンを押す、**Then** 補完候補に代わってディレクトリ履歴のリストが開く。
4. **Given** 履歴が保存されている、**When** アプリを再起動する、**Then** 両方の履歴を再び選択できる。
5. **Given** 既に履歴にある値で再検索する、**When** 検索が開始される、**Then** その値は重複せず履歴の先頭に移る。
6. **Given** 正規表現検索で不正なパターンを入力した、**When** 検索を開始しようとする、**Then** 開始前にエラーが示され、両履歴は変わらない。

---

### User Story 2 - 保存件数を調整する (Priority: P2)

利用者は設定画面で両履歴に共通の保存件数を変更できる。保存件数を減らすと古い項目から削除される。

**Why this priority**: 履歴の使いやすさと、端末に残す検索条件の量を利用者が決められる。

**Independent Test**: 設定画面で保存件数を変更し、履歴の件数と再起動後の設定値を確認する。

**Acceptance Scenarios**:

1. **Given** 初期設定のまま、**When** 設定画面を開く、**Then** 履歴の保存件数として 20 件が表示される。
2. **Given** いずれかの履歴が 3 件以上ある、**When** 保存件数を 2 件に設定する、**Then** 両方の履歴がそれぞれ新しい 2 件以内になり、設定値は再起動後も維持される。
3. **Given** 履歴が保存されている、**When** 保存件数を 0 件に設定する、**Then** 両方の保存済み履歴が削除され、以降は保存されない。
4. **Given** 設定画面で範囲外または整数でない値を入力した、**When** 設定を確定しようとする、**Then** 値は受け付けられず、許容範囲が示される。

---

### User Story 3 - ディレクトリのパスを補完する (Priority: P2)

利用者は検索ディレクトリ欄へパスを入力する途中で、存在するディレクトリの候補を選び、残りのパスを補える。

**Why this priority**: 長いパスや類似したフォルダ名の入力ミスを減らす。

**Independent Test**: 同じ親の下に複数のディレクトリとファイルを用意し、部分入力に一致するディレクトリだけが候補になることを確認する。

**Acceptance Scenarios**:

1. **Given** 入力済みの親ディレクトリが存在する、**When** その直下の名前を途中まで入力する、**Then** 前方一致する直下のディレクトリが候補に表示され、通常ファイルは表示されない。
2. **Given** 補完候補が表示されている、**When** 候補を選ぶ、**Then** 検索ディレクトリ欄がその候補の完全なパスになり、検索は自動実行されない。
3. **Given** 補完候補が表示されている、**When** キーボードで候補を移動・確定または閉じる、**Then** マウス操作なしで補完を使うか取り消せる。
4. **Given** ホームディレクトリの下に対象のフォルダがある、**When** `~/` に続けて名前を入力する、**Then** 一致するフォルダが候補に表示され、選択後のパスで検索できる。
5. **Given** Windows 上でドライブ付き絶対パスまたは UNC 共有パスの親が読める、**When** 末尾の名前を途中まで入力する、**Then** 直下の一致するディレクトリを候補に表示し、選択後のパスで検索できる。
6. **Given** Windows 上でホームディレクトリの下に対象のフォルダがある、**When** `~\` に続けて名前を入力する、**Then** その表記の候補が表示され、選択後のパスで検索できる。

### Edge Cases

- 検索テキストまたは検索ディレクトリが空白だけの場合、検索は受け付けられず、履歴にも追加されない。
- ディレクトリが存在しない、または検索を開始できない場合、両履歴に追加されない。開始後に中断・失敗した場合は追加済みの履歴を維持する。
- 正規表現検索のパターンが不正な場合、検索は開始せず、両履歴に追加されない。
- 補完元の親ディレクトリが存在しない、読めない、または候補がない場合、候補は表示されず、入力済みの文字列は保持される。
- 履歴にあるディレクトリが移動・削除されても項目は表示される。選択時に検索は始まらず、検索時には通常の入力検証が適用される。
- パスに空白、日本語、同じ接頭辞を持つ名前が含まれても、候補の表示と選択で文字列が変質しない。
- 相対パスは補完候補を表示しない。`~/` と Windows の `~\` 以外の `~` から始まる表記も補完対象外とする。
- Windows では `~\` もホーム省略表記として扱う。`C:folder`、`\folder`、未接続の UNC 共有、デバイスパス、拡張長パスからは補完候補を表示しない。
- 日本語入力の変換中は、候補確定のキー操作が変換を妨げない。
- 履歴や設定の読み書きに失敗しても、現在の検索入力と検索機能は利用でき、保存失敗は利用者に分かる形で通知される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: アプリは、必須入力と検索可能なディレクトリを確認し、正規表現検索ではパターンの妥当性も確認して検索を開始した時点で、検索テキストと検索ディレクトリを別々の履歴に保存しなければならない。不正な正規表現は開始前にエラーを示して保存せず、結果が 0 件、検索開始後の中断・失敗は保存対象とする。
- **FR-002**: アプリは、各履歴を新しい順に保持し、同じ値の再利用時は重複を作らず先頭に移さなければならない。
- **FR-003**: アプリは、両入力欄の専用ボタンからそれぞれの履歴を表示するドロップダウンリストを提供し、選択した値を対応する入力欄へ反映しなければならない。履歴の選択だけで検索を開始してはならない。
- **FR-004**: アプリは、履歴と保存件数の設定をアプリの再起動後も利用できるよう、利用者の端末内に保持しなければならない。検索条件やパスを外部へ送信してはならない。
- **FR-005**: 設定画面は、検索テキストと検索ディレクトリの両履歴に共通する保存件数を 0 から 50 件の整数で設定でき、初期値を 20 件としなければならない。
- **FR-006**: 保存件数を減らした場合、アプリは両履歴から上限を超える古い項目を直ちに削除しなければならない。0 件にした場合は両履歴を消去し、新たな検索条件を保存してはならない。
- **FR-007**: アプリは、検索ディレクトリ欄に OS に応じた絶対パスまたはホーム省略表記を入力中、入力済みの親ディレクトリの直下から、入力中の末尾名に前方一致するディレクトリを補完候補として提示しなければならない。相対パスと通常ファイルは候補に含めてはならず、履歴ボタンを押した場合は補完候補に代えて履歴を表示しなければならない。
- **FR-008**: 補完候補の選択は検索ディレクトリ欄のみを更新し、検索を開始してはならない。候補の選択・取消しはマウスとキーボードで操作できなければならない。
- **FR-009**: 親ディレクトリを参照できない場合、アプリは補完候補を表示せず、入力文字列と検索操作を妨げてはならない。
- **FR-010**: 履歴と補完の操作は、日本語入力中の文字確定、既存のフォルダ選択、ドラッグ＆ドロップ、通常の検索開始操作を妨げてはならない。
- **FR-011**: 履歴または設定の保存に失敗した場合、アプリは検索を続けられる状態を維持し、利用者へ保存できなかったことを通知しなければならない。
- **FR-012**: 履歴、補完候補、設定項目は、現在選択されている表示言語に対応した案内を示さなければならない。
- **FR-013**: アプリは、`~/` 形式（Windows では `~\` 形式も）で指定されたディレクトリを利用者のホームディレクトリとして扱い、補完候補を選ばずに検索を開始した場合も同じ場所を検索しなければならない。履歴には入力欄で使用した表記を保存しなければならない。
- **FR-014**: Windows では、ドライブ付き絶対パスと UNC 共有パスを補完対象とし、`~/` と `~\` をホームディレクトリとして解決しなければならない。現在位置に依存するドライブ相対・ルート相対パス、デバイスパス、拡張長パスは補完対象とせず、候補選択前の入力表記を変えてはならない。

### Key Entities

- **検索テキスト履歴**: 過去に受け付けられた検索テキストの重複のない順序付き一覧。新しい利用が先頭に来る。
- **検索ディレクトリ履歴**: 過去に受け付けられた検索ディレクトリのパスの重複のない順序付き一覧。新しい利用が先頭に来る。
- **履歴保存件数設定**: 両履歴に適用する最大件数。0 は履歴を保存しない状態を表す。
- **パス補完候補**: 入力中の親ディレクトリ直下に存在し、入力中の末尾名と一致するディレクトリのパス。`~/` 入力時はその表記を維持する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 保存済みの検索テキストと検索ディレクトリを、利用者が各入力欄で 3 操作以内に再入力できる。
- **SC-002**: 履歴を保存した後にアプリを再起動しても、両履歴と保存件数の設定が全件保持される。
- **SC-003**: 保存件数を減らした後、両履歴の表示件数が設定値以下になり、削除された古い項目は再起動後も現れない。
- **SC-004**: ローカルの読み取り可能な親ディレクトリにある補完候補が、末尾名の入力から 1 秒以内に表示される。ネットワーク共有の応答待ちは画面の入力を止めない。
- **SC-005**: 用意したパス補完の利用試験で、空白・日本語・`~/` を含む入力について、候補選択後のパスが意図した実ディレクトリを 100% 指し示す。
- **SC-006**: マウスを使わずに、両履歴の選択とパス補完候補の選択・取消しを完了できる。

## Assumptions

- 履歴への追加は検索の開始時に行う。文字入力中や履歴選択時には追加しない。
- 履歴の一致判定は入力値の完全一致とする。大文字・小文字、パスの表記違いは統合しない。
- 保存件数は両履歴で共通とし、既定値を 20 件、設定可能な範囲を 0～50 件とする。
- 補完対象は現在入力している末尾のディレクトリ名のみとし、親ディレクトリの再帰的な探索は行わない。`~/` は利用者のホームディレクトリを指す。
- 既存の設定画面と表示言語の仕組みを利用する。
