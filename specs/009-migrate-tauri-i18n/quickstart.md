# 検証ガイド: tauri-plugin-i18n への移行

## 前提

- `009-migrate-tauri-i18n` の実装が完了している。
- Node.js、npm、Rust、Tauri の実行環境がある。
- 確認対象は [表示契約](contracts/localization-contract.md) と [データモデル](data-model.md)。

## 自動検証

リポジトリ直下で順に実行する。

```sh
npm ci
npm test
npm run lint
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo fmt --manifest-path src-tauri/Cargo.toml --check
```

**期待結果**: すべて終了コード0。日英の翻訳資源が読み込まれ、キー欠落、読込失敗、保存失敗、既存設定の互換、Rust の出力文言の確認が成功する。警告や欠落した翻訳は確認して解消する。

## デスクトップ実機確認

```sh
npm run tauri dev
```

1. 保存値がない状態で端末の優先言語を日本語にして起動する。設定画面と検索画面、メニューが日本語になる。
2. 端末の優先言語を日本語以外にして再起動する。デフォルト設定なら英語になる。日本語を明示選択した場合は日本語のままとなる。
3. 検索条件と結果を表示したまま日英を切り替える。画面、開いている通知、メニューが変わり、検索条件・結果・セル値は変わらない。設定画面を開いてから切替完了まで30秒以内であることを確認する。
4. 日英それぞれで CSV と Excel を出力する。列見出し、一致種別、シート名が要求時の言語で揃う。
5. 日英それぞれでエラーを発生させる。画面の案内は表示言語、アプリ自身の診断ログの説明文は英語となる。
6. 設定を保存して再起動する。既存の保存値 `default|ja|en` がそのまま有効であることを確認する。

## 失敗系の確認

- 自動テストで日本語の翻訳キーを一つ欠落させ、その文言だけ英語へ代替することを確認する。
- 自動テストでプラグインの読込、端末言語の取得、設定保存を個別に失敗させる。起動が続き、利用可能な英語案内または選択後の言語での保存失敗通知が出る。
- 開発ビルドでプラグインから利用可能な言語として `en` と `ja` が見えることを確認する。空なら Cargo ワークスペースと `src-tauri/locales` の同梱を確認する。
