# 言語表示と Tauri 連携の契約

## 設定画面

- 常に `default`、`ja`、`en` の3択を示し、現在の選択値と表示言語を示す。
- 選択直後にアプリが作成した文言を更新する。検索条件、結果、選択中の項目と利用者データは保持する。
- 保存に失敗しても現在の起動中は選択を維持し、現在の言語で失敗を通知する。
- 既存の保存キー `exlgrep.language` と3種類の値を継続使用する。

## 翻訳キー

- `en.yml` と `ja.yml` を唯一の翻訳正本とする。各ファイル先頭に4要素の説明コメントを置く。キーは画面・メニュー・出力で再利用し、非翻訳のコード定数とは区別する。
- 利用者向け文言の解決順は、対象言語のキー、英語の同一キー、英語の必須キー `common.translationUnavailable`。翻訳キー文字列を画面へ露出しない。
- プレースホルダーの形式と差込値の意味は日英で一致させる。ファイル名、パス、検索語、セル値は翻訳対象外。
- 通知は文言キーと差込値を保持し、表示時の言語で解決する。

## プラグイン境界

- 起動時に翻訳データを読み込み、保存設定と端末言語から有効言語を決めてプラグインへ設定してからアプリ画面を表示する。
- 切替時はプラグインの言語と React の有効言語、ネイティブメニューを同じ値へ更新する。翻訳ファイルはアプリに同梱し、外部通信を行わない。
- React 管理の DOM は React が描画する。プラグインの `data-i18n` による DOM 直接書換えを併用しない。
- プラグイン読込失敗時も同じ `en.yml` をフロントエンドで解析して起動を継続し、失敗の説明を英語でログへ記録する。

## 既存 IPC

| 境界 | 入力 | 成功時 | 失敗時 |
|---|---|---|---|
| `set_menu_locale` | `language: ja|en` | 対応言語のアプリメニュー | 既存の `CommandError.code`、利用者には表示言語の案内 |
| `export_results` | `ExportRequest.language: ja|en` | 指定言語の CSV・Excel 見出し | 不正値拒否、英語の内部理由と翻訳済みの画面通知 |
| 検索・プレビュー | 既存の言語非依存データ | 表示時の言語で進捗・エラーを説明 | 生の内部エラー文言を画面へ出さない |

エラーコード、進捗の `phase`、出力要求の形は 008 から変更しない。出力要求の言語は処理中に変えない。

## 受け入れ確認

1. 保存済み `ja` と `en`、未設定と `default` の4状態で起動言語を確認する。
2. 表示中に切替え、画面・通知・メニューが更新され、検索状態が残ることを確認する。
3. 日本語キーを欠落させ、その文言だけ英語になることを確認する。
4. CSV・Excel を両言語で作り、見出しと一致種別を確認する。
5. 保存・端末言語取得・プラグイン読込の失敗時に英語フォールバックと継続利用を確認する。
