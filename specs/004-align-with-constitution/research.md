# Research & Architecture Decisions: プロジェクト憲章準拠のプログラム改修

**Feature Branch**: `004-align-with-constitution`  
**Date**: 2026-09-26  
**Status**: Completed  

## 1. 定数管理アーキテクチャの選定 (Constitution Principle II)

### 決定内容 (Decision)
- **Rust (バックエンド)**: `src-tauri/src/constants.rs` を新設し、システム全体で使用される定数をモジュール別に分類して定義する。利用箇所では `// 定数参照: crate::constants::<CONSTANT_NAME> を使用` とコメントを明記する。
- **TypeScript (フロントエンド)**: `src/constants/index.ts`（必要に応じてカテゴリ別分割）を新設し、UI文言、設定値、イベント名、コマンド名、テーブル寸法などを集約して定義する。利用箇所では `// 定数参照: CONSTANTS.<NAME> を使用` とコメントを明記する。
- **例外事項の遵守**: 憲章原則IIに基づき、数値の `0` および空文字列 `""` のみ直接記述を許容し、それ以外の数値・マジックナンバー・固定文字列は100%定数化する。

### 採用理由 (Rationale)
- プロジェクト全体で定数を集約することで、仕様変更時の修正漏れを根絶し、コードの自己説明性を最大化できる。
- 定数参照コメントを義務付けることで、レビュー時および将来のAIによる改修時にも定数利用が意図的であることを保証できる。

### 検討した代替案 (Alternatives Considered)
- *各ファイル内にローカル定数（`const FOO: &str`）を定義する案*: 一元化されず重複定義が発生するため却下。
- *環境変数や設定ファイル（JSON/YAML）へ外部化する案*: 静的型検査が効かず実行時オーバーヘッドが生じるため、コンパイル時定数としてのコード集約を採用。

## 2. 4要素ヘッダコメントの標準化 (Constitution Principle III)

### 決定内容 (Decision)
すべてのファイル、モジュール、構造体、クラス、関数、メソッドに対し、以下の4必須要素を含むヘッダコメントを統一フォーマットで適用する。

#### Rust 用フォーマット (`///` または `//!`)
```rust
/// ## 処理内容
/// [関数の目的と処理手順の詳細説明]
///
/// ## 引数
/// - `param_a`: `Type` - [引数の役割と前提条件]
///
/// ## 戻り値
/// - `Result<T, String>`: 成功時は...、失敗時は日本語エラーメッセージ
///
/// ## エラー / 例外発生条件
/// - [エラーが発生する条件、panicの有無（panic排除）]
///
/// ## 変更履歴
/// - v1.0.0 (2026-09-26, AI Agent): 初版作成 / 憲章原則III準拠
```

#### TypeScript 用フォーマット (`/** ... */`)
```typescript
/**
 * ## 処理内容
 * [コンポーネントまたは関数の詳細説明]
 *
 * ## 引数
 * @param paramA - [型と説明]
 *
 * ## 戻り値
 * @returns [型と説明]
 *
 * ## エラー / 例外発生条件
 * [発生し得る例外またはエラーハンドリング方針]
 *
 * ## 変更履歴
 * - v1.0.0 (2026-09-26, AI Agent): 初版作成 / 憲章原則III準拠
 */
```

### 採用理由 (Rationale)
- 4つの必須情報（説明、入出力、エラー条件、変更履歴）をセクションとして定型化することで、記載漏れを機械的に検知可能とし、開発者とAI双方にとって可読性を担保する。

### 検討した代替案 (Alternatives Considered)
- *標準的なJSDoc/Rustdocの1行コメントのみとする案*: 憲章原則IIIの必須4要件（特に変更履歴やエラー条件）が欠落しやすいため却下。

## 3. 静的解析およびスタイルガイド完全準拠 (Constitution Principle IV)

### 決定内容 (Decision)
- **Rust Clippy の警告ゼロ化**:
  - `system_cmd.rs`: `sort_by` を `sort_by_key(|a| std::cmp::Reverse(a.is_default))` へ置換。
  - `csv_export.rs`: 不要な参照借用 `&[...]` を `[...]` へ置換。
  - `engine.rs`: `SearchEngine` に `impl Default` を実装。
  - `parser.rs`: `cancel_flag.map_or(false, ...)` を `cancel_flag.is_some_and(...)` へ置換。
  - `cargo clippy --all-targets -- -D warnings` をCIおよびローカル検証の必須ゲートとする。
- **Rustfmt の適用**: `cargo fmt` を実行し、全コードのインデントと改行を言語標準に統一。
- **TypeScript 型検査**: `tsc --noEmit` および `npm run build` をエラー・警告ゼロでパスさせる。

### 採用理由 (Rationale)
- Clippyおよびrustfmtの完全遵守は、Rustコミュニティのベストプラクティスであり、バグの未然防止とコードベースの一貫性を確立する。

## 4. 日本語ファースト＆品質検証方針 (Constitution Principle I)

### 決定内容 (Decision)
- UI上のすべてのラベル、プレースホルダー、トースト通知、ダイアログ文言、エクスポートヘッダー（CSV/Excel）、およびエラーメッセージを自然かつ正確な日本語で統一する。
- 成果物出力時およびビルド前に、`<PAD>`、`<pad>` などの不要特殊トークンや文字化けが発生していないかを検証するチェック手順を定義する。
- OSやサードパーティライブラリが返却する英語エラーについては、ユーザー向けに日本語の親切なメッセージへマッピングして表示する。

### 採用理由 (Rationale)
- ユーザーに直接届くテキストの品質を保証し、不自然な機械翻訳や不要トークン混入による混乱・不信感を排除するため。

---

## 5. 堅牢なエラーハンドリングとテスト戦略 (Constitution Principle V)

### 決定内容 (Decision)
- バックエンドのパニック要因（`unwrap()`、`expect()` の無警戒な使用）を徹底的に精査し、`Result<T, String>` や適切なエラー型へ置き換える。
- 単体テストの拡充:
  - 定数モジュールのテスト（定義値の整合性検証）
  - エラーハンドリングのテスト（無効なパスや破損ファイルに対する安全な返却）
  - スニペット・パーサーのUTF-8境界安全性の継続検証
- フロントエンドでのエラーバウンダリとトーストによる親切なエラー通知。

### 採用理由 (Rationale)
- デスクトップアプリケーションにおいて異常終了はユーザーの信頼を大きく損ねるため、安全なフォールバックと完全なテストパスを担保する。
