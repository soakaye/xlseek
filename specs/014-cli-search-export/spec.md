# Feature Specification: コマンドライン検索・結果保存 (CLI Search Export)

**Feature Branch**: `014-cli-search-export`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "GUIを開く事なくcsv, excelに検索結果を保存するコマンドラインツールを作成する。各種オプションはコマンドラインオプションで指定する"

## Clarifications

### Session 2026-09-29
- Q: 一部のExcelファイルを読めずに検索を続けた場合、コマンドの終了状態をどう扱いますか？ → A: 全件成功・一部失敗・全体失敗を別々の終了状態で示す。
- Q: 出力先に既存ファイルがある場合、上書きをどう扱いますか？ → A: 既定では拒否し、明示的な上書きオプションが指定された場合だけ許可する。ただし検索対象ファイルへの上書きは常に禁止する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - GUIを使わない検索と結果保存 (Priority: P1)

利用者は端末から検索対象とキーワード、出力先を指定して実行し、GUIを起動せずに検索結果をCSVまたはExcelファイルとして取得する。

**Why this priority**: GUI操作や画面表示を必要とせず、スクリプトや定期処理から検索結果を利用できることがこの機能の中心価値である。

**Independent Test**: 検索語を含むブックを用意し、端末から検索を実行してCSVとExcelの各形式で結果ファイルが作成され、内容が画面版の検索結果と一致することを確認する。

**Acceptance Scenarios**:

1. **Given** 検索可能なExcelファイルを含むフォルダーと有効な検索語があるとき、**When** 利用者が検索対象、検索語、CSV出力先を指定して実行したとき、**Then** GUIを開かずに検索が完了し、指定先に結果を含むCSVが保存される。
2. **Given** 同じ検索条件とExcel形式の出力先が指定されているとき、**When** 利用者がコマンドを実行したとき、**Then** 指定先に検索結果を含むExcelファイルが保存される。
3. **Given** 検索語に一致する項目がないとき、**When** 利用者が検索を実行したとき、**Then** 一致件数0件として正常終了し、列見出しを含む空の結果ファイルが保存される。

### User Story 2 - 検索条件を引数で指定する (Priority: P1)

利用者は検索語、検索対象、対象拡張子、大小文字の区別、正規表現、数式・コメント・図形内テキスト・非表示シートの検索有無などをコマンドラインオプションで指定し、実行ごとに検索方法を調整する。

**Why this priority**: GUIを介さずに実行するには、検索設定をコマンド自体から再現可能に指定できる必要がある。

**Independent Test**: オプションの異なるコマンドを実行し、大文字小文字、正規表現、検索対象種別、対象拡張子の各指定が検索結果に反映されることを確認する。

**Acceptance Scenarios**:

1. **Given** 検索対象に大小文字が異なる値があるとき、**When** 利用者が大小文字を区別する設定と区別しない設定でそれぞれ検索したとき、**Then** 各設定に応じた一致結果が得られる。
2. **Given** 検索語を正規表現として扱う指定があるとき、**When** 利用者が検索を実行したとき、**Then** 指定パターンに一致する項目が結果に含まれる。
3. **Given** 検索対象種別や対象拡張子が明示されているとき、**When** 利用者が検索したとき、**Then** 指定した種別と拡張子だけが検索結果に反映される。
4. **Given** 利用者がオプションの使い方を確認したいとき、**When** ヘルプ表示を要求したとき、**Then** 利用可能なオプション、値、既定動作が表示され、ファイル検索は開始されない。

### User Story 3 - 入力や保存の失敗を把握する (Priority: P2)

利用者は不正な検索条件、読み取れない検索対象、または書き込めない出力先がある場合、原因を特定できるメッセージを端末で確認し、処理が成功したかどうかを判別する。

**Why this priority**: 自動処理に組み込む場合、失敗を検知して再実行や入力修正につなげられることが必要である。

**Independent Test**: 不正な正規表現、存在しない検索対象、書き込み不可の出力先をそれぞれ指定し、失敗理由が表示され成功として扱われないことを確認する。

**Acceptance Scenarios**:

1. **Given** 指定された正規表現が不正なとき、**When** 利用者が検索を実行したとき、**Then** 検索を開始せず、どの条件を修正すべきか分かるエラーを表示する。
2. **Given** 検索対象が存在しない、または出力先に書き込めないとき、**When** 利用者が実行したとき、**Then** 該当するパスと失敗理由を表示し、処理の失敗を示す。
3. **Given** 出力先に検索対象ではない既存ファイルがあるとき、**When** 上書きオプションなしで実行したとき、**Then** 対話的な確認を行わず保存を拒否し、既存ファイルを保持する。
4. **Given** 出力先に検索対象ではない既存ファイルがあるとき、**When** 上書きオプションを指定して実行したとき、**Then** 対話的な確認を行わず検索結果に置き換える。
5. **Given** 出力先が検索対象ファイルと同じとき、**When** 上書きオプションを指定して実行したとき、**Then** 保存を拒否し、検索対象ファイルを保持する。

### Edge Cases

- 検索対象フォルダーに対応ファイルがない場合は、0件の結果として完了する。
- 一部のブックが破損、読み取り不可、またはパスワード保護されている場合は、そのファイルの問題を通知し、他の読み取り可能なファイルの検索を続ける。
- 空ファイルは読取失敗として扱う。有効な空ブックは0件として正常終了する。対象ブックをすべて開けない場合は見出しだけの結果を保存して全体失敗とし、正常な0件一致と区別する。
- 検索対象のパスがファイルの場合はそのファイルだけを検索し、フォルダーの場合は配下を再帰的に検索する。
- 検索語が空、必須オプションが不足、またはオプション値が不正な場合は、検索を開始せず使い方とエラーを表示する。
- 出力先が検索対象ファイルと同じ場合は、上書きオプションの有無にかかわらず保存前に拒否する。既存の出力ファイルは、明示的な上書きオプションがなければ保存前に拒否する。
- CSVまたはExcelの保存中にエラーが発生した場合、不完全な結果ファイルを成功扱いにせず、保存失敗を通知する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者はGUIを起動せずに端末から検索処理を実行し、検索結果を保存できなければならない。
- **FR-002**: 利用者は検索対象としてExcelファイルまたはフォルダーを指定できなければならない。フォルダー指定時は配下のフォルダーも検索対象としなければならない。
- **FR-003**: システムは `.xlsx`、`.xlsm`、`.xls`、`.xlsb` のExcelファイルを検索対象として扱わなければならない。
- **FR-004**: 利用者は検索語、出力形式（CSVまたはExcel）、出力先をコマンドラインオプションで指定できなければならない。
- **FR-005**: 利用者は大小文字の区別、正規表現の使用、値・数式・コメント/メモ・図形内テキストの検索、非表示シートの扱い、および対象拡張子をコマンドラインオプションで個別に指定できなければならない。
- **FR-006**: オプションを省略した場合、大小文字を区別しない、正規表現を使用しない、数式を検索する、コメント/メモを検索する、図形内テキストを検索しない、非表示シートを除外する、4種類の対応Excel拡張子を対象とする、という既定動作を適用しなければならない。
- **FR-007**: 検索結果は画面版と同じ結果項目を含むCSVまたはExcelファイルとして保存されなければならない。Excel形式は `.xlsx` とする。
- **FR-008**: 一致が0件の場合も、結果項目の列見出しを含むファイルを保存し、正常な検索完了として扱わなければならない。
- **FR-009**: 利用者はヘルプを要求してオプションの説明と既定動作を確認できなければならない。
- **FR-010**: 入力やオプションの不備、検索または保存の失敗を端末上に理解可能なメッセージで通知し、終了状態によって全件成功・一部ファイルの失敗・検索全体の失敗をそれぞれ区別できなければならない。
- **FR-011**: 破損または読み取りできない対象ファイルがあっても、他の対象ファイルの検索を継続し、問題のあったファイルを利用者に通知しなければならない。読み取り可能なブックがある場合は、結果を保存したうえで一部失敗を示す終了状態を返さなければならない。対象ブックが1件以上あり、すべて開けない場合は列見出しだけの結果を保存し、全体失敗を示す終了状態を返さなければならない。保存失敗はこれらより優先して全体失敗とする。
- **FR-012**: 既存の出力ファイルは既定では上書きを拒否し、明示的な上書きオプションが指定された場合だけ置き換えを許可しなければならない。検索対象ファイルへの上書きは、そのオプションが指定されていても常に禁止しなければならない。上書きのための対話的な確認は行ってはならない。
- **FR-013**: 検索処理および結果出力はローカル環境内で完結し、検索対象の内容や検索語を外部へ送信してはならない。

### Key Entities

- **検索要求**: 検索対象、検索語、検索条件、および結果形式と保存先をまとめた実行単位。
- **検索結果項目**: 一致したファイル、シート、セルまたは図形、該当内容、数式、および一致種別を示す情報。
- **実行結果**: 検索の完了状態、一致件数、保存先、および発生したファイル単位または処理単位のエラー。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 有効な検索要求を端末から1回実行することで、GUIを一度も開かずに検索結果ファイルを作成できる。
- **SC-002**: 指定可能な4種類すべてのExcel入力形式から検索した結果を、CSVおよびExcel（`.xlsx`）の両形式で保存できる。
- **SC-003**: 有効な検索条件では、保存ファイルに含まれる一致項目と件数が画面版で同じ条件を実行した結果に一致する。
- **SC-004**: 不正な入力または保存に失敗したケースのすべてで、利用者は成功と誤認せず、端末上のメッセージから修正対象を特定できる。
- **SC-005**: 0件検索でも、利用者は結果ファイルを開いて列見出しと0件の結果を確認できる。

## Assumptions

- 検索対象はローカルで読み取り可能なファイルまたはフォルダーとし、フォルダーは再帰的に検索する。
- 検索対象形式、検索設定の既定値、および結果項目は既存のExcel Grep検索機能と同じにする。
- Excel出力は `.xlsx` 形式とし、CSVとExcelの文字コード・列構成・見出し言語は画面版の既存出力に合わせる。
- 出力先がすでに存在する場合は、利用者がコマンドラインオプションで明示的に上書きを指定しない限り処理を拒否する。検索対象ファイルへの上書きは常に禁止する。
- 実行中の入力とパス構成は他プロセスが変更しない前提とする。明示上書き時は保存先とその親ディレクトリも他プロセスが変更しない前提とする。検出した入力衝突や保存先の変更は拒否するが、明示上書きは第三者による同時変更を排除する仕組みを提供しない。
- ファイル単位の読み取りエラーは通知して検索を続けるが、検索要求全体の妥当性または結果保存に関するエラーは実行失敗として扱う。

## Out of Scope

- GUI画面の変更やGUIからのCLI呼び出し。
- 検索結果の別形式（PDF、JSON等）への保存。
- ネットワーク上のサービスやクラウドストレージ独自APIを介した検索。
