## 1. 前提条件と環境準備

- **OS**: Windows 10 / 11
- **ランタイム**: Node.js 18+ (推奨 v24+), Rust 1.77+
- **テスト用サンプルファイル**: `tests/fixtures/sample_report.xlsx`

```bash
# 依存パッケージのインストールとビルド検証
npm install
npm run build
cd src-tauri && cargo check
```

## 2. エンドツーエンド (E2E) 検証シナリオ

### シナリオ 1: フォルダ選択領域へのフォルダドラッグ＆ドロップ (DnD)

1. アプリケーションを開発モードまたはビルド成果物から起動:
   ```bash
   npm run tauri dev
   ```
2. エクスプローラーを開き、テスト用フォルダ（例: `tests/fixtures`）を検索バーのフォルダ選択入力枠へドラッグする。
   - **期待結果**: 入力枠がエメラルド色の破線枠に変化し、「フォルダをここにドロップ」の案内オーバーレイが表示される。
3. マウスボタンを離してドロップする。
   - **期待結果**: フォルダ入力欄に該当フォルダの絶対パスが設定され、破線ハイライトが消える。自動で検索は始まらず待機状態となる。
4. 今度はエクスプローラーから Excel ファイル（例: `sample_report.xlsx`）を同入力枠へドロップする。
   - **期待結果**: ファイルの親フォルダの絶対パスが自動解決され、入力欄に設定される。

---

### シナリオ 2: 既定登録アプリによるワンクリック起動

1. 検索バーで任意のキーワード（例: `Total`）を検索し、左ペインの一覧から一致項目をクリックして選択する。
2. 右ペインのヘッダーにある起動ボタン（スプリットボタン）を確認する。
   - **期待結果**: 左側のメインボタンに固定ラベル「アプリで開く」と表計算アイコンが表示される。マウスカーソルを合わせると、ツールチップに現在OSに登録されている既定アプリ名（例: `Microsoft Excel で開く`）が表示される。
3. 「アプリで開く」メインボタンをクリックする。
   - **期待結果**: OS の既定表計算アプリ（Excel 等）が起動し、対象の Excel ファイルが開かれる。

---

### シナリオ 3: ポップアップメニューからのサポートアプリ選択起動

1. 起動ボタン右側の「▼（メニュー展開）」ボタンをクリックする。
   - **期待結果**: 300ミリ秒以内にサポートアプリ一覧を含むポップアップメニューが表示される。
   - 各アプリの表示名（例: `Microsoft Excel`, `LibreOffice Calc` 等）が表示され、既定アプリには「(既定)」バッジが付与されている。
   - メニュー末尾に「別のプログラムを選択...」が表示されている。
2. サポートアプリ一覧から任意のアプリをクリックする。
   - **期待結果**: ポップアップメニューが閉じ、選択したアプリケーションで該当 Excel ファイルが起動する。
3. 再度▼ボタンを押し、今度はメニューの外側をクリック、または Esc キーを押す。
   - **期待結果**: アプリを起動することなくポップアップメニューが閉じる。

---

### シナリオ 4: 「別のプログラムを選択...」の呼び出し

1. プレビューヘッダーの「▼」ボタンをクリックしてポップアップメニューを表示する。
2. メニュー末尾の「別のプログラムを選択...」をクリックする。
   - **期待結果**: ポップアップメニューが閉じ、Windows 標準の「プログラムから開く」ダイアログが表示される。

---

### シナリオ 5: 起動エラー時の安全な通知

1. アンインストール等により実行ファイルが存在しないアプリをシミュレート、または不正なパスで起動要求が発生した場合。
   - **期待結果**: アプリケーションがクラッシュせず、画面下部等に「アプリケーションを起動できませんでした: [詳細]」というエラーメッセージがトースト通知される。
