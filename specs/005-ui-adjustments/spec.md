## User Scenarios & Testing *(mandatory)*

### User Story 1 - 検索バー・フォルダ入力欄のキー入力制御と拡張子選択 (Priority: P1)

利用者が日本語環境において検索キーワードやフォルダパスを入力する際、IMEによる漢字・仮名変換の確定処理（Enterキー押下）によって意図しない検索が誤爆発火せず、意図通りの文字入力と検索実行が行える。また、対象拡張子の選択を直感的なボタントグルで行える。

**Why this priority**: 日本語入力環境でのIME確定Enterによる誤検索発火は、デスクトップ検索ツールにおける最大のユーザー体験の阻害要因であり、入力をストレスなく完了させるために最優先で担保すべき必須要件である。

**Independent Test**: 検索キーワード欄およびフォルダパス欄で日本語（全角文字列）を入力し、Enterキーを押下して変換を確定した際、検索が実行されないことを確認する。変換確定後に検索キーワード欄で再度Enterキーを押下した際のみ検索が実行されることを確認する。

**Acceptance Scenarios**:

1. **Given** 検索キーワード入力欄にフォーカスがある状態で日本語IMEが有効なとき、**When** 利用者が文字列を入力して変換候補をEnterキーで確定したとき、**Then** 検索処理は開始されず、入力欄に変換確定済みの文字列がそのまま維持される。
2. **Given** 検索キーワード入力欄にテキストが確定入力されているとき、**When** 利用者がEnterキーを押下したとき、**Then** 検索処理が即座に開始される。
3. **Given** フォルダパス入力欄にフォーカスがあるとき、**When** 利用者がEnterキーを押下したとき、**Then** 検索処理は開始されず、入力中の状態および入力フォーカスがフォルダパス入力欄内に維持される（Enterキー押下は無視される）。
4. **Given** 対象拡張子ボタン群が表示されているとき、**When** 利用者が選択中の拡張子をクリックしたとき、**Then** 残りの選択数が1つ以上であればその拡張子が除外され、選択数が残り1つの場合は除外が防止される。

### User Story 2 - ステータスバーの進捗表示改善とフォルダスキャン可視化 (Priority: P2)

検索実行中、利用者がアプリケーションの現在の処理状況（フォルダ内のファイル探索中なのか、ファイルの解析・セル走査中なのか、完了したのか）を一目で把握でき、処理の停滞やフリーズではないことを確信できる。

**Why this priority**: 大規模フォルダや階層の深いディレクトリを検索する際、ファイル読み込み前のフォルダ走査フェーズで何のフィードバックもないと、利用者はアプリが応答不能になったと誤認する。進行状況の明確なフィードバックは信頼性に直結する。

**Independent Test**: 検索を開始した直後、ステータスバーにおいてプログレスバーがメッセージの手前に固定幅で表示され、フォルダ探索中フェーズのアニメーションとパス表示が行われた後、ファイル解析・セル走査の進捗パーセント表示へとスムーズに移行することを目視確認する。

**Acceptance Scenarios**:

1. **Given** 検索が開始された直後（ファイル解析の前段階）、**When** アプリケーションが対象フォルダを探索しているとき、**Then** ステータスインジケーターおよびプログレスバーが探索中状態（アニメーション表示）となり、探索中のフォルダパスがステータス欄に明示される。
2. **Given** ファイルの解析が順次行われているとき、**When** 各ファイルのセル走査が進むとき、**Then** 固定幅プログレスバーに進捗割合（%）が反映され、走査済みファイル数/総ファイル数および現在処理中のファイル名が表示される。
3. **Given** 検索が完了したとき、**When** 最終結果が表示されたとき、**Then** インジケーターが完了状態（緑点灯）になり、プログレスバーが100%となり、ヒット件数・走査ファイル数・所要秒数が表示される。
4. **Given** ステータスバーが表示されているとき、**When** 画面全体を閲覧したとき、**Then** 内部エンジン情報（Calamine Engine等の技術名称）は非表示となり、利用者にとって価値のある情報（進捗・件数・エクスポートボタン等）のみが整理されて表示される。

### User Story 3 - 周辺セルプレビューの縦横両方向スクロールと固定見出し (Priority: P3)

検索結果の一致セルを選択した際、利用者は周辺セルのコンテキスト（前後行・前後列）を縦横両方向に滑らかにスクロールして確認でき、行見出し（行番号）および列見出し（A, B, C...）が常に画面端に固定表示（Freeze Panes）されるため、セルの位置関係を常に見失わずに把握できる。

**Why this priority**: 表計算データは縦にも横にも広がりを持つため、固定見出しがないスクロールはデータの読み違えを招く。Excel同様のフリーズペイン（見出し固定）を提供することで、データ閲覧効率を最大化する。

**Independent Test**: プレビュー領域で十分な行数（30行以上）および列数のデータが表示されている状態で、マウスホイールやドラッグによって縦方向および横方向にスクロールした際、列見出し（A, B, C...）が上部に、行番号（#および数値）が左側に固定され続け、任意のセルをクリックした際にアドレスと内容が数式バーに正しく反映されることを確認する。

**Acceptance Scenarios**:

1. **Given** プレビューグリッドが表示されているとき、**When** 利用者が下方向にスクロールしたとき、**Then** 最上部の列見出し行（A, B, C...）および左上の角（#）が上部に固定されたまま、データ行がスクロールする。
2. **Given** プレビューグリッドが表示されているとき、**When** 利用者が右方向にスクロールしたとき、**Then** 最左列の行番号列（#および行番号）が左端に固定されたまま、データ列がスクロールする。
3. **Given** プレビュー表示中の任意のセルがあるとき、**When** 利用者がそのセルをクリックしたとき、**Then** セルが選択枠で強調され、数式バーの名前ボックスにセル番地（例: A12）、値表示部にそのセルの数式または表示値が連動して表示される。

### Edge Cases

- **IME変換中のEnter連打**: 変換確定操作で素早くEnterを複数回押下した場合でも、確定のためのEnterと検索実行のためのEnterを確実に識別し、意図しない検索が暴発しないこと。
- **全角スペースのみ・空文字でのEnter押下**: キーワード欄で全角・半角スペースのみの状態でEnterが押下された場合、無効な検索処理を実行せず初期状態を保つこと。
- **フォルダパス欄でのドラッグ＆ドロップと手入力の併用**: フォルダを外部からドラッグ＆ドロップしてパスを入力した後、末尾をキーボードで追記・編集してEnterを押した場合でも、検索は実行されず編集内容のみが正しく保持されること。
- **拡張子選択の全解除抑止**: 選択中の拡張子が残り1つの状態でその拡張子をクリックした場合、選択解除を防止して最低1つの拡張子が常に有効であり続けること。
- **行数・列数が極端に多いプレビューデータ**: 行数が30行以上、列数が10列以上に及ぶ大きなデータセットでも、固定見出し（Freeze Panes）のスタイル崩れやスクロールの引っ掛かりが発生しないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 検索キーワード入力欄は、日本語入力システム（IME）の変換確定操作によるEnterキー押下を検知し、変換確定時のEnterでは検索処理を実行してはならない（MUST NOT）。
- **FR-002**: 検索キーワード入力欄は、テキストが確定している状態でEnterキーが押下された場合にのみ、検索実行処理を開始しなければならない（MUST）。
- **FR-003**: フォルダパス入力欄は、Enterキー押下による検索実行アクションを完全に排除し、入力中のEnterキー押下を無効化（イベント伝播抑止・既定動作抑止）して入力フォーカスを入力欄内に維持しなければならない（MUST）。
- **FR-004**: フォルダパス入力欄は、日本語IMEによる変換確定操作を妨げることなく、通常の文字編集（入力・削除・移動）およびドラッグ＆ドロップ、ダイアログからの選択をデフォルト動作として維持しなければならない（MUST）。
- **FR-005**: 対象拡張子（.xlsx, .xlsm, .xlsb, .xls）は個別のトグルボタンとして配置され、クリックによって選択/除外を切り替え可能とし、最低1つの拡張子は常に選択状態が維持されなければならない（MUST）。
- **FR-006**: ステータスバーのプログレスバーは、ステータスメッセージの手前（左側）に固定幅（幅44相当）で配置され、進捗メッセージと重複せず整然と表示されなければならない（MUST）。
- **FR-007**: 検索処理開始直後のファイル読み込み前段階において、対象フォルダを走査・探索中である旨の視覚的アニメーションおよび探索中フォルダパスをステータス欄に表示しなければならない（MUST）。
- **FR-008**: ステータスバーから内部エンジン名称（Calamine Engine等）の固定表示を削除し、検索状態とエクスポート機能に画面領域を集約しなければならない（MUST）。
- **FR-009**: 周辺セルプレビューグリッドは、縦方向および横方向の双方向スクロールを独立してサポートし、表示領域のサイズ制約によりスクロールが遮断されてはならない（MUST）。
- **FR-010**: 周辺セルプレビューグリッドは、縦スクロール時に列見出し（A, B, C...）、横スクロール時に行番号（#および行番号数値）、左上角（#ヘッダー）をそれぞれ固定（Freeze Panes）表示しなければならない（MUST）。
- **FR-011**: デザインプロトタイプ（HTMLモック）は、スタンドアローン動作環境において縦スクロール動作を実機確認できるよう、30行以上の十分なサンプルプレビューデータを備え、React本番実装と完全同期していなければならない（MUST）。

### Key Entities

- **検索入力設定（Search Input Configuration）**: ユーザーが入力したキーワード文字列、対象フォルダパス文字列、有効化されている対象拡張子の集合、大文字小文字/正規表現/数式/コメント/非表示シート等の検索フラグ群。
- **検索進行状態（Search Progress State）**: 現在のフェーズ（待機中、フォルダ探索中、ファイル解析・セル走査中、完了、中断）、探索中フォルダパス、走査進捗率（%）、処理済みファイル数/総対象ファイル数、現在処理中ファイル名、所要時間。
- **セルプレビューグリッド表示（Cell Preview Grid View）**: 対象セルの前後行および前後列から構成されるマトリクス構造。列情報（列記号ラベル、キー）、行情報（行番号数値）、各セル値（表示文字列、数式文字列、一致ターゲットフラグ、選択フラグ）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 日本語IMEを利用したキーワード入力において、変換確定操作に伴うEnterキー押下によって検索が誤爆発火する発生率が0%であること。
- **SC-002**: フォルダパス入力欄にフォーカスがある状態で利用者がEnterキーを押下した際、検索処理が開始されないこと（誤発火率0%）。
- **SC-003**: 検索実行時、ファイル走査開始前の「探索中」段階がプログレスバーおよびステータステキストによって即座（100ms以内）に表示され、ユーザーに進行状態が伝達されること。
- **SC-004**: 周辺セルプレビューグリッドを縦方向・横方向にそれぞれスクロールした際、列見出しおよび行番号見出しが常時視野内に維持され、100%の見出し視認性が確保されること。
- **SC-005**: プロトタイプ（HTMLモック）において、プレビュー領域に最低30行以上のデータが表示され、標準的なウィンドウ高さ（420px〜900px）において縦スクロールバーが正常に出現し、スクロール検証が可能であること。
- **SC-006**: 対象拡張子トグルボタンにおいて、利用者がすべての拡張子を誤って全解除することが構造的に防止され、常時1つ以上の拡張子が選択されていること。

## Assumptions

- **対象プラットフォーム**: 主に macOS および Windows 環境のデスクトップ利用者を想定し、macOS (WebKit / Safari) における IME確定Enterの先行イベント発火挙動、および Windows / Chromium における IMEイベント挙動の双方が同一のユーザー体験で吸収されることを前提とする。
- **標準入力動作の尊重**: フォルダ入力欄でのEnterキー押下は検索をトリガーしないが、OSネイティブのファイル選択ダイアログの起動、ドラッグ＆ドロップ、パス文字列のコピー＆ペーストは標準的なデスクトップ操作に準拠する。
- **プレビューデータ範囲**: バックエンドから取得される周辺セルの範囲は前後数行・前後数列であるが、デザインモックおよびUI表示においては十分な行数（30行以上）を扱ってもパフォーマンス低下やレイアウト崩れが発生しない設計とする。
- **デザインプロトタイプの位置付け**: `design/mainui/index.html` は本プロジェクトにおける生きた仕様（Living Spec）として扱われ、React実装と振る舞い・スタイリング・文言が完全に1:1で同期される。
