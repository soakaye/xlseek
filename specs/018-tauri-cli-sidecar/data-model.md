# Data Model: Bundle xlseek-cli as a Tauri Sidecar

This feature adds no search data or persistent application data. The models below describe file artifacts passed through build and distribution.

## BuildTarget

- **target_triple**: Rust target identifier selected for the Tauri distribution. Examples: `x86_64-pc-windows-msvc`, `aarch64-apple-darwin`.
- **platform_extension**: `.exe` on Windows; empty on macOS/Linux. Follows Tauri Sidecar naming rules.
- **source_artifact**: `xlseek-cli` generated by Cargo for the same target triple.
- **validation**: The triple must be nonempty and correspond to a Cargo target for the intended OS/CPU. A nonzero CLI build or missing source artifact fails the operation.

## SidecarArtifact

- **base_name**: `binaries/xlseek-cli` referenced by the Tauri configuration.
- **staged_path**: `<base_name>-<target_triple><platform_extension>`, staged under `src-tauri/binaries/` relative to `tauri.conf.json`.
- **release_version**: The same version as the `xlseek-cli` Cargo package. The GUI and CLI are built from the same workspace checkout.
- **execution_state**: `executable` after a successful build; on failure, stop the distribution process. Preserve executable permissions in Unix/macOS packages.
- **lifecycle**: Cargo build → stage with target-suffixed name → embed through Tauri bundler → user launches directly from the installed package.

## DesktopDistributionArtifact

- **platform**: Windows, macOS, or Linux.
- **architecture**: Windows x64, macOS Intel x64 or Apple Silicon arm64, or Linux x64 GNU.
- **application_package**: An installable distribution containing the Tauri GUI and corresponding `SidecarArtifact`.
- **invariant**: The CLI in a package matches its OS/CPU target. A package missing the CLI or containing a binary from another release is invalid.
- **user_access**: The CLI is not launched through the Tauri UI or registered on `PATH`; users launch the executable directly from its installation location.

## State Transition

`not built → built for target triple → staged under Sidecar name → embedded in distribution → direct execution checked after installation`

If input is missing or mismatched at any stage, that stage must fail instead of reporting success.
