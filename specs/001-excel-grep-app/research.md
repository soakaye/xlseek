# 技術調査と設計決定: Excel Grep デスクトップアプリケーション (Research & Decisions)

**機能ブランチ**: `001-excel-grep-app`  
**日付**: 2026-09-25  
**仕様書**: [spec.md](./spec.md)

---

## 概要

本機能は、大量の Excel ファイル群（.xlsx, .xlsm, .xlsb, .xls）からキーワードや正規表現に一致するセル・数式・コメントを瞬時に横断検索し、直感的な 2 ペイン画面でスプレッドシートプレビューや外部連携を行うデスクトップアプリケーションです。ユーザーからの「**Tauri + Rust** で作成する」という指定に基づき、各技術選定・アーキテクチャ設計・パフォーマンス要件の検証を行いました。

---

## 技術決定事項 (Decisions & Rationales)

### 1. アプリケーション基盤: Tauri v2 + Rust バックエンド

- **決定 (Decision)**: [Tauri v2](https://v2.tauri.app/) を採用し、コア検索エンジンを Rust、UI を Web テクノロジー（TypeScript + React / Tailwind CSS）で構築する。
- **根拠 (Rationale)**:
  - **フットプリントとメモリ**: Electron と比較してバンドルサイズが極めて小さく（10MB前後）、常駐メモリ消費量も数十MBに抑えられる。
  - **安全性とパフォーマンス**: Rust によるメモリ安全な並列スレッド実行と、OS ネイティブの WebView（Windows では WebView2）を利用した軽快な描画を両立できる。
  - **ネイティブ連携**: ファイルダイアログ、シェル起動（Excelで開く、エクスプローラーで表示）、クリップボード操作などをセキュアな IPC で呼び出せる。
- **検討した代替案 (Alternatives Considered)**:
  - *Electron*: Node.js と Chromium を抱えるため起動時間・メモリ消費（数百MB〜1GB）が大きく、高速・軽量という製品コンセプトに反する。
  - *WPF / C# (.NET)*: Windows 固有の技術であり、将来のマルチプラットフォーム展開（macOS/Linux）が困難。
  - *Python + PyQt*: 配布サイズ（PyInstaller等）が巨大化し、大量ファイルの並列パース速度で Rust に及ばない。

---

### 2. Excel パースライブラリ: `calamine` クレート

- **決定 (Decision)**: Rust の高速 Excel 読み込みライブラリ [`calamine`](https://crates.io/crates/calamine) (v0.26+) を採用する。
- **根拠 (Rationale)**:
  - **対応フォーマット**: `.xlsx` (OpenXML), `.xlsm` (マクロ付き), `.xlsb` (バイナリ形式), `.xls` (旧Excel 97-2003 BIFF8) を単一の統一インターフェースで高速にパース可能。
  - **パフォーマンス**: 読み込み専用に特化して最適化されており、不要なスタイリングやフォント情報を省いてセル値・数式・シート構造を極小のメモリで走査できる。
  - **数式・コメントの取得**: セル値（String, Float, Bool, Error）に加え、フォーミュラ文字列の抽出やシート名一覧の高速列挙に対応。
- **検討した代替案 (Alternatives Considered)**:
  - *umya-spreadsheet*: 読み書き双方に対応しているが、パース速度が遅く、Grep 走査用としてはメモリ消費が大きい。
  - *rust-xlsxwriter*: 書き込み専用ライブラリのため検索には不適合（エクスポート時には候補となる）。

---

### 3. 並列走査エンジン & 中断制御アーキテクチャ

- **決定 (Decision)**: [`rayon`](https://crates.io/crates/rayon) によるマルチスレッド並列ファイル走査 + `std::sync::atomic::AtomicBool` (Cancellation Token) による即時中断制御を採用する。
- **根拠 (Rationale)**:
  - **CPU コアの活用**: 大量の Excel ファイル（数百〜数千件）を CPU コア数に合わせてワークスティーリング方式で並列処理することで、逐次処理と比べて 5〜10 倍の走査スループットを達成。
  - **即時キャンセル**: ユーザーが「CANCEL」を押下した際、共有のアトミックフラグを `true` に設定し、各スレッドがファイル単位・シート単位のループ境界で即座に処理を中断・脱出する。
  - **ストリーミング通知**: ヒットした結果は Tauri のイベント機構（`tauri::Emitter` または mpsc チャンネル）を通じて、走査中であってもフロントエンドへ順次ストリーミング送信する。
- **検討した代替案 (Alternatives Considered)**:
  - *非同期 I/O (tokio のみ)*: Excel の解凍（ZIP展開）と XML/バイナリパースは CPU-bound な処理であるため、tokio のスレッドプールのみではコンテキストスイッチの負荷が増大する。rayon のブロッキング並列プールが最適。
  - *全件走査完了後のバッチ一括送信*: 1,000 件以上のファイルを走査する際に初期表示まで数十秒待たされるため、プログレッシブなストリーミング通知が不可欠。

---

### 4. フロントエンド UI & 仮想スクロール (Virtual Scrolling)

- **決定 (Decision)**: TypeScript + React + Tailwind CSS + [`@tanstack/react-virtual`](https://tanstack.com/virtual/latest) を採用する。
- **根拠 (Rationale)**:
  - **デザインプロトタイプの完全再現**: `design/mainui/index.html` で構築・検証された Tailwind CSS スタイル（左右 2 ペイン、独立したパス専用行、数式バー、シートタブバー、欠けないマージン設計）をそのままコンポーネント化可能。
  - **10,000 件規模の描画性能**: 仮想スクロールにより、DOM 上には可視領域の数十行のみを描画し、10,000 件以上の検索結果が蓄積されてもメモリ消費と再レンダリング時間を一定（60fps）に維持。
  - **Lucide Icons**: `lucide-react` により、プロトタイプと完全に同一のモダンなアイコン表示を実現。
- **検討した代替案 (Alternatives Considered)**:
  - *バニラ HTML/JS (WebView内)*: コンポーネントの状態管理（検索中状態、選択行、プレビュー連動、仮想スクロール）が複雑化し、メンテナンス性が低下する。
  - *ページネーション (50件送り)*: 検索結果を連続して見渡したい Grep ツールの用途において、頻繁なページ送りがユーザー体験を損なう。

---

### 5. 周辺セルプレビューの高速抽出アルゴリズム

- **決定 (Decision)**: 一致したセルの座標 `(row, col)` を基準に、`min_row = max(0, row - 3)`, `max_row = row + 3`, `min_col = max(0, col - 2)`, `max_col = col + 2` の 7行 × 5列 前後の周辺セルマトリクスのみを抽出してフロントエンドに転送する。
- **根拠 (Rationale)**:
  - **超軽量データ転送**: シート全体（数万行×数十列）を JSON 化して IPC 通信するとメガバイト単位のオーバーヘッドが生じるが、周辺 35 セル程度であれば数キロバイト以下となり、クリックから 10 ミリ秒以内にプレビューが切り替わる。
  - **文脈把握に十分な範囲**: 前後 3 行・前後 2 列のデータがあれば、表の見出しや前後の集計行・メモを即座に確認できる。
  - **固定ヘッダー対応**: 抽出された行番号・列記号（A, B, C...）を CSS `sticky` で固定表示し、スクロール時の視認性を確保。

---

### 6. 結果エクスポート方式

- **決定 (Decision)**:
  - **CSV エクスポート**: Rust の `csv` クレートを使用し、UTF-8 (BOM付き、Excelで文字化けしない形式) で高速出力。
  - **Excel (XLSX) エクスポート**: Rust の `rust_xlsxwriter` クレートを採用し、ヘッダー装飾や自動列幅調整を適用した見やすい `.xlsx` ブックを生成。
- **根拠 (Rationale)**:
  - 日本語環境の Excel で直接ダブルクリックして開けるよう、CSV には BOM を付与。
  - XLSX 形式のエクスポートにより、セル値だけでなく一致種別やハイライト情報も保持可能。
