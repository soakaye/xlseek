# Quickstart: Shape 内テキスト検索の検証

## 前提

- `tests/fixtures/shapes/` に同じ内容の `sample.xlsx`、`sample.xlsm`、`sample.xls`、`sample.xlsb` を用意する。各ブックには可視シート上のテキストボックス、通常図形、グループ内の子図形2個、同じ語を含むセル値・数式、文字なし図形、非表示シート上の図形を置く。
- 各形式の `edge.xlsx`、`edge.xlsm`、`edge.xls`、`edge.xlsb` で分割テキスト、アンカー欠損、破損図形を確認する。画像・グラフの文字が誤ヒットしないことも確認する。`tests/fixtures/shapes/README.md` に各ファイルの作成元または入手元、作成・変換手順、SHA-256、図形名・文字列・アンカー・期待結果件数を記録し、検証前に照合する。
- [検索契約](contracts/shape-search-contract.md) と [データモデル](data-model.md) を判定基準にする。

## 自動検証

リポジトリのルートで実行する。

```sh
npm test
npm run build
npm run lint
(cd src-tauri && cargo test)
(cd src-tauri && cargo clippy --all-targets -- -D warnings)
(cd src-tauri && cargo fmt --check)
```

Rust テストでは4形式それぞれの Shape 抽出、グループ内の個別結果、オン・オフ、検索条件、非表示シート、破損入力、キャンセル、CSV / Excel 出力を検証する。フロントエンドテストではトグル、種別表示、Shape 選択時のセルプレビュー抑止、日英表示を検証する。いずれかの形式で期待結果が欠けた場合は未完了とする。

## 画面での確認

1. `npm run tauri -- dev` でアプリを起動し、4形式の fixture があるフォルダを指定する。
2. Shape 検索をオンにし、Shape だけにある検索語を入力する。テキストボックス、通常図形、グループ内の各子図形がそれぞれ1件ずつ現れ、画像・グラフは現れないことを確認する。
3. Shape 検索をオフにして再検索し、Shape 結果が0件になることを確認する。セル値と数式の結果は各オプションに従い残る。
4. アンカーのある図形とない図形の結果をそれぞれ選び、結果選択からファイル、シート、Shape 名、一致箇所を確認できるまでの操作を数え、各3操作以内であることを記録する。どちらもセルプレビューを開かず全文を表示し、アンカーがある図形だけ実際のセル番地を補助情報として示す。
5. 大文字・小文字、正規表現、非表示シートの各条件を切り替えて結果を確認する。
6. CSV と Excel に出力し、画面上の Shape の全件が Shape 名と文字列を保っていることを確認する。表示言語を切り替えて項目名と結果種別も確認する。
7. `design/mainui/index.html` のオプションと結果表示が実画面と一致することを確認する。

## 性能と異常系

各ファイルに検索語と一致する Shape を1件以上含む、ローカル保存の100ファイル・合計100 MB の検証用フォルダを使う。同一端末で OS、CPU、メモリ、ストレージを記録し、検索開始から画面に最初の結果が出るまでを計測して10秒以内であること、検索中に画面を操作できることを確認する。検索中にキャンセルし、操作可能な状態へ戻ることを確認する。破損した図形を含むブックを混ぜてもアプリが異常終了せず、他の読取可能な結果が欠けないことを確認する。
