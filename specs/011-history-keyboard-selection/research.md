# Research: 履歴一覧のキーボード操作

## 履歴ボタンから一覧への移動

- **Decision**: 既存の履歴項目ボタンをフォーカス対象として使う。履歴ボタンからの Tab は表示順に従って先頭へ移し、下矢印でも先頭へ移す。
- **Rationale**: `SearchBar.tsx` は履歴ボタンの直後に項目ボタンを置いている。既存要素と画面構造を利用できる。
- **Alternatives considered**: 入力欄にフォーカスを固定して一覧を仮想選択する方法は、仕様が求める項目へのフォーカス移動に合わず、既存の画面構造を大きく変える。

## 一覧内の移動と確定

- **Decision**: 履歴項目のキー処理で Tab を末尾から先頭へ循環させ、上下矢印は両端で留める。現在項目の視覚表示と `aria-selected` は実際のフォーカスに合わせる。Enter は既存の `selectOption` を通して確定する。
- **Rationale**: 既存の入力欄向け `handleListKeyDown` は項目ボタンでは動かない。履歴項目に限って処理を追加すれば、既存のディレクトリ補完を保てる。Enter の標準クリックとキー処理の二重発火には注意する。
- **Alternatives considered**: 一覧全体を新しい選択コンポーネントへ置き換える方法は変更範囲が広く、保存や補完の既存動作にも影響しやすい。

## 閉じる操作、空状態、IME

- **Decision**: Escape は一覧を閉じて対応する入力欄へフォーカスを戻す。履歴が空なら Tab の通常移動を妨げない。項目数が変化したら有効な項目だけを対象にし、日本語入力の変換中はキー操作を無視する。
- **Rationale**: 既存の領域内フォーカス移動は `handleFieldBlur` が維持し、領域外クリックは既存処理が閉じる。入力欄の IME 保護も既にあるため、項目側へ同じ考えを適用する。
- **Alternatives considered**: 空一覧をフォーカス対象にしたり、履歴データに選択位置を保存したりする必要はない。

## 検証手段

- **Decision**: `tests/search-history-ui.test.tsx` の Vitest と Testing Library の操作テストを拡張し、スタンドアローン UI モックも同期する。
- **Rationale**: 同じ画面の履歴、フォーカス離脱、補完、IME の回帰テストが既にある。追加依存なしで両履歴の要件を確認できる。
- **Alternatives considered**: 新しいテスト基盤の導入は不要。

未解決の技術的明確化事項はない。
