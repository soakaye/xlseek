# Feature Specification: 履歴一覧のキーボード操作

**Feature Branch**: `011-history-keyboard-selection`

**Created**: 2026-09-27

**Status**: Draft

**Input**: User description: "履歴表示時の履歴リストへの遷移および選択をキー操作で可能とする"

## Clarifications

### Session 2026-09-27

- Q: 履歴一覧の最後の項目で Tab キーを押したとき、フォーカスはどこへ移るべきですか? → A: 先頭項目へ戻り、Escape キーで一覧を閉じる。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 履歴をキーだけで選ぶ (Priority: P1)

利用者は検索テキストまたは検索ディレクトリの履歴を表示した後、マウスを使わずに一覧へ移り、希望する項目を選んで入力欄に反映できる。

**Why this priority**: 履歴を表示できても一覧へ移れなければ、キーボードだけでの再入力が完了しないため。

**Independent Test**: 両方の履歴に複数項目を用意し、それぞれ履歴ボタンにフォーカスした状態からキーだけで項目を選び、対応する入力欄のみが更新されることを確認する。

**Acceptance Scenarios**:

1. **Given** 検索テキストまたは検索ディレクトリの履歴が表示され、対応する履歴ボタンにフォーカスがある、**When** Tab キーまたは下矢印キーを押す、**Then** 対応する一覧の最初の履歴項目へフォーカスが移り、現在の項目が見分けられる。
2. **Given** 検索ディレクトリの履歴が表示され、最初の項目にフォーカスがある、**When** 下矢印キーで次の項目へ移り Enter キーを押す、**Then** そのディレクトリが入力欄に反映され、履歴一覧が閉じる。
3. **Given** 検索テキストの履歴が表示され、項目にフォーカスがある、**When** 上下矢印キーで項目を移動して Enter キーを押す、**Then** フォーカス中の項目だけが検索テキスト欄に反映され、検索は開始されない。
4. **Given** 検索テキストまたは検索ディレクトリの履歴が複数項目を表示し、いずれかの項目にフォーカスがある、**When** Tab キーを押す、**Then** 次の項目へ移り、最後の項目からは一覧を閉じずに最初の項目へ戻る。

---

### User Story 2 - 選択せずに履歴を閉じる (Priority: P2)

利用者は履歴を確認した後、入力内容を変えずにキー操作で一覧を閉じ、元の入力作業へ戻れる。

**Why this priority**: 誤選択を避け、入力中の条件を保ったまま操作を続けるため。

**Independent Test**: 両方の履歴で項目へ移動した後に Escape キーを押し、一覧が閉じて入力値が維持されることを確認する。

**Acceptance Scenarios**:

1. **Given** 履歴項目にフォーカスがある、**When** Escape キーを押す、**Then** 一覧が閉じ、入力値は変わらず、対応する入力欄へフォーカスが戻る。
2. **Given** 履歴一覧が表示されている、**When** 一覧外をクリックする、**Then** 一覧が閉じ、入力値は変わらない。

### Edge Cases

- 履歴が 0 件のときは空であることを示し、Tab キーで空の項目にフォーカスさせず、次の通常の操作対象へ移れる。
- 最初の項目で上矢印キー、最後の項目で下矢印キーを押しても、選択位置は一覧の範囲内に留まる。
- 履歴が 1 件のときに Tab キーを押しても、同じ項目に留まる。
- 表示中に履歴が更新されて項目数が減った場合も、存在しない項目は選択されない。
- 日本語入力の変換・確定中のキー操作は履歴の移動や選択として扱わない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は、検索テキストと検索ディレクトリの両方について、履歴ボタンへキーで移動し、キーで履歴を表示できなければならない。受け入れ条件: 両ボタンを Tab キーで選び、Enter キーで対応する一覧を表示できる。
- **FR-002**: 検索テキストと検索ディレクトリの両方について、利用者は履歴ボタンから Tab キーまたは下矢印キーで先頭の履歴項目へ移れなければならない。受け入れ条件: 項目が 1 件以上ある場合、どちらのキーでも先頭項目にフォーカスが移る。
- **FR-003**: 検索テキストと検索ディレクトリの両方について、利用者は履歴項目間を上下矢印キーまたは Tab キーで移動でき、現在の項目を視覚的に識別できなければならない。受け入れ条件: 上下矢印キーでは 1 項目ずつ移動して両端で留まり、Tab キーでは次の項目へ移動して最後の項目から一覧を閉じずに先頭へ戻る。
- **FR-004**: 利用者はフォーカス中の履歴項目を Enter キーで選択できなければならない。受け入れ条件: 値が対応する入力欄へ反映され、一覧が閉じ、検索は開始されない。
- **FR-005**: 利用者は履歴項目から Escape キーで選択を取り消せなければならない。受け入れ条件: 一覧が閉じ、入力値は維持され、対応する入力欄へフォーカスが戻る。
- **FR-006**: 履歴が空の場合、利用者は空の一覧を確認でき、キー操作で次の通常の操作対象へ進めなければならない。受け入れ条件: 空の項目が選択対象にならず、Tab キーの移動が止まらない。
- **FR-007**: 履歴操作は既存の検索条件入力、日本語入力、ディレクトリ補完、およびマウスによる履歴選択を妨げてはならない。受け入れ条件: 各操作は従来どおり利用でき、履歴選択は検索を自動開始しない。

### Key Entities

- **検索テキスト履歴項目**: 過去の検索テキストを表す、順序のある選択肢。
- **検索ディレクトリ履歴項目**: 過去の検索ディレクトリを表す、順序のある選択肢。
- **現在の履歴項目**: キー操作の対象として利用者に示され、確定時に入力欄へ反映される項目。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用意した検索テキスト・検索ディレクトリの履歴選択試験で、利用者がマウスを使わずに目的の項目を選び、対応する入力欄へ反映できる割合が 100% である。
- **SC-002**: 履歴を表示した状態から先頭項目を選ぶまで、利用者が必要とするキー操作は 2 回以内である。
- **SC-003**: 履歴を表示した状態から、20 件の履歴の任意の項目へキーだけで到達し、選択または取消しを完了できる。
- **SC-004**: 選択・取消し・空の履歴・日本語入力中の試験で、意図しない検索開始および入力値の変更が 0 件である。

## Assumptions

- 対象は既存の検索テキスト履歴と検索ディレクトリ履歴であり、ディレクトリ補完候補の操作方法の追加は対象外とする。
- 履歴の保存条件、順序、件数、再起動後の保持は既存仕様を引き継ぐ。
- 履歴ボタンから先頭項目への移動は Tab または下矢印、項目間の移動は上下矢印または Tab、確定は Enter、取消しは Escape を用いる。
