# Quickstart: 履歴一覧のキーボード操作を確認する

## 前提

- この機能の実装後に実行する。
- 検索テキストと検索ディレクトリの履歴をそれぞれ 20 件用意する。0 件・1 件も個別に確認する。
- 期待する画面動作は[UI 契約](contracts/history-keyboard-ui-contract.md)を参照する。

## 自動検証

リポジトリ直下で実行する。

```sh
npm test -- tests/search-history-ui.test.tsx
npm run lint
npm run build
cd src-tauri
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

操作テストは両履歴のフォーカス移動・選択・取消し・空状態・IME と、既存の補完操作を確認する。ビルド、Lint、Rust の各コマンドは終了コード 0、警告 0 を合格とする。

## 画面での確認

リポジトリ直下で `npm run tauri dev` を実行する。

1. 検索テキスト履歴ボタンへ Tab で移り、Enter で一覧を開く。Tab または下矢印で先頭項目へ移る。現在項目が見分けられることを確認する。
2. 上下矢印で項目を移り、両端では止まることを確認する。Tab で末尾から先頭へ戻り、一覧が閉じないことを確認する。
3. 20 件の先頭・中間・末尾の項目をそれぞれキーで選べることを確認する。末尾から Tab で先頭へ戻ることも確認する。20 件すべてへの到達と選択・取消しは自動テストの結果で確認する。
4. Enter で項目を選び、検索テキスト欄だけが変わり、検索が始まらないことを確認する。
5. 検索ディレクトリ履歴でも手順 1～4 を繰り返す。ディレクトリ補完候補の表示・選択が従来どおり動くことも確認する。
6. 両履歴の項目から Escape を押し、値を変えずに一覧が閉じ、対応する入力欄へ戻ることを確認する。
7. 履歴 0 件では空表示を確認し、Tab で次の操作対象へ進めることを確認する。1 件では Tab を押しても同じ項目に留まることを確認する。
8. 日本語入力の変換・確定中に履歴の移動・選択や検索が誤発火しないことを確認する。

画面状態と保存済み履歴の関係は[データモデル](data-model.md)を参照する。
