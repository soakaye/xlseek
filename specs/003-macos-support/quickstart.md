## 1. 前提条件と環境準備

- **OS**: macOS 12 Monterey 以降 (Apple Silicon / Intel 双方対応) または Windows 10/11
- **ランタイム**: Node.js 18+ (推奨 v24+), Rust 1.77+
- **テスト用サンプルファイル**: `tests/fixtures/sample_report.xlsx`

```bash
# 依存パッケージのインストールとビルド検証
npm install
npm run build
cd src-tauri && cargo check
```

---

## 2. エンドツーエンド (E2E) 検証シナリオ

### シナリオ 1: OS ネイティブウィンドウフレームおよびタイトルバーの検証

1. アプリケーションを開発モードで起動:
   ```bash
   npm run tauri dev
   ```
2. ウィンドウ上部を確認する:
   - **macOS での期待結果**:
     - ウィンドウ上部左側に OS 標準の赤・黄・緑のトラフィックライトボタンが表示される。
     - タイトルバー中央（OS 標準位置）に「Excel Grep」が表示される。
     - 旧カスタムタイトルバー（Webview 内の独自描画バー）が完全になく、画面上部の無駄な二重枠線がない。
   - **Windows での期待結果**:
     - ウィンドウ上部右側に標準の最小化・最大化・閉じるボタンが表示される。
3. ネイティブ操作をテストする:
   - タイトルバー領域をドラッグしてウィンドウがスムーズに移動することを確認する。
   - タイトルバーをダブルクリックして、ウィンドウがズーム/最大化されることを確認する。
   - トラフィックライトの黄色ボタンをクリックして Dock へ最小化され、再度開けることを確認する。
4. 画面最下部のステータスバーを確認する:
   - **期待結果**: 旧タイトルバーにあった「Calamine Engine」バッジおよびバージョン「v0.1.0」がステータスバーに綺麗に収まり、視認可能であること。

---

### シナリオ 2: macOS における Finder 選択表示 (`open_in_folder`)

1. 検索バーで任意のキーワードを検索し、検索結果一覧から項目をクリックしてプレビューを表示する。
2. プレビューヘッダーの「フォルダを開く」ボタンをクリックする。
   - **期待結果**:
     - macOS 上で Finder が前面にアクティブ化される。
     - 該当ファイルが属する親フォルダが開かれ、かつ**該当ファイルがハイライト選択された状態**で表示される。

---

### シナリオ 3: macOS における対応表計算アプリの検出と起動

1. プレビューヘッダーの「アプリで開く」スプリットボタンを確認する。
   - **期待結果**: マウスホバー時のツールチップに、macOS で `.xlsx` の既定となっているアプリ（例: `Microsoft Excel で開く` または `Numbers で開く`）が表示される。
2. メインボタン（左側）をクリックする。
   - **期待結果**: macOS の既定アプリで該当ファイルが直接起動する。
3. 起動ボタン右側の「▼（メニュー展開）」ボタンをクリックする。
   - **期待結果**:
     - ポップアップメニューが表示され、インストールされている対応アプリ（例: `Microsoft Excel`, `Numbers`, `LibreOffice Calc` 等）が一覧表示される。
     - 各アプリのアイコンヒントに応じた適切なバッジ/アイコンが表示される。
4. 一覧から「Numbers」または「Microsoft Excel」を選択する。
   - **期待結果**: 選択したアプリケーションで該当ファイルが開く。

---

### シナリオ 4: 「別のプログラムを選択...」による macOS アプリピッカー起動

1. プレビューヘッダーの「▼」ボタンをクリックしてポップアップメニューを表示する。
2. メニュー末尾の「別のプログラムを選択...」をクリックする。
   - **期待結果**:
     - macOS ネイティブのファイル選択ダイアログが表示される。
     - 初期ディレクトリとして `/Applications` が開かれ、`.app` アプリケーションを選択可能であること。
3. 任意のアプリケーション（例: テキストエディタや別ビューア）を選択する。
   - **期待結果**: 選択したアプリケーションでファイルが開かれる（キャンセル時は何事もなくダイアログが閉じる）。

---

### シナリオ 5: macOS アプリケーションメニューと標準ショートカット

1. macOS 最上部のシステムメニューバーを確認する:
   - **期待結果**: 「Excel Grep」「編集」「ウィンドウ」メニューが存在すること。
2. 検索バーのキーワード入力欄でテキストを入力し、以下のショートカットを実行する:
   - `⌘A` : 全選択
   - `⌘C` : コピー
   - `⌘V` : 貼り付け
   - `⌘Z` : 元に戻す
   - **期待結果**: すべての標準ショートカットが自然に機能すること。
3. `⌘W` を押下してウィンドウを閉じる、または `⌘Q` を押下してアプリケーション全体を正常終了できることを確認する。

---

### シナリオ 6: POSIX パスでのドラッグ＆ドロップとクリップボードコピー

1. Finder からテスト用フォルダ（またはファイル）を検索バーのフォルダ選択領域へドラッグ＆ドロップする。
   - **期待結果**: `/Users/...` から始まる正しい POSIX パスが入力欄にセットされる。
2. プレビューヘッダーの「パスをコピー」をクリックし、Terminal に貼り付ける（`⌘V`）。
   - **期待結果**: 正しい POSIX 形式のファイルパスが貼り付けられる。
