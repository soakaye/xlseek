# 機能仕様書: マルチプラットフォーム対応 (macOS対応・システム標準タイトルバー・OS固有機能の同等実装)

**機能ブランチ**: `003-macos-support`

**作成日**: 2026-09-25

**ステータス**: ドラフト (Draft)

**入力**: ユーザー記述: "マルチプラットフォーム対応。今回はmacOS対応。マルチプラットフォーム化のためタイトルなどはシステム標準のものを使用するように変更。Windows用とは条件コンパイルで機能を分けるが同等機能を実装する。"

## Clarifications

### Session 2026-09-25

- Q: システム標準のタイトルバーへの移行は、macOS だけでなく Windows も含めた全プラットフォームで OS ネイティブのウィンドウ装飾（decorations: true）を有効にして独自コントロールボタンを廃止する方針で統一しますか？ → A: macOS/Windows 双方で OS ネイティブ装飾を有効化し、フロントエンドの独自タイトルバーとウィンドウ制御ボタン（最小化・最大化・閉じる）を完全廃止して OS ネイティブに統一する (Option A)。
- Q: macOS 環境において、起動ボタンのポップアップメニューから「別のプログラムを選択...」が選ばれた際、どのような挙動で同等機能を提供しますか？ → A: macOS のアプリケーション選択ダイアログ（/Applications を初期表示）を表示し、選択された .app で対象ファイルを起動する (Option A)。
- Q: macOS 環境において、標準的なキーボード操作（⌘C/⌘V によるコピー・ペースト、⌘Q による終了、⌘W によるウィンドウクローズ等）をサポートするための OS 標準アプリケーションメニュー（メニューバー）を提供しますか？ → A: macOS 標準のアプリケーションメニュー（編集・ウィンドウ・終了等）を有効化し、OS 標準ショートカット（⌘C/⌘V/⌘A/⌘Q/⌘W等）を完全サポートする (Option A)。

## ユーザーシナリオ & テスト *(必須)*

### ユーザーストーリー 1 - 全プラットフォームでのOS標準ウィンドウフレームへの統一 (優先度: P1)

ユーザーは、実行しているオペレーティングシステム（macOS または Windows）ネイティブの標準ウィンドウタイトルバーおよびウィンドウコントロール（macOS では左側の赤黄緑トラフィックライトボタン、Windows では右側の最小化・最大化・閉じるボタン）を利用して、ウィンドウの移動、リサイズ、最小化、最大化、終了を自然かつ直感的に操作できる。特定 OS 向けの独自カスタムタイトルバーによる違和感をなくし、プラットフォーム標準の操作感を提供する。

**この優先度である理由**: マルチプラットフォーム化におけるユーザー体験の基盤であり、各プラットフォームでの第一印象と基本操作（ウィンドウ制御）をOSネイティブの作法に適合させる最重要項目であるため。

**独立テスト方法**: macOS および Windows 環境のそれぞれでアプリケーションを起動し、OS標準のネイティブタイトルバーが表示され、プラットフォーム標準のウィンドウコントロールおよびタイトルバーのドラッグ移動・ダブルクリック操作がOS既定の動作通りに機能することを確認する。

**受入シナリオ**:

1. **前提**: macOS 環境でアプリケーションを起動する。
   **もし**: ウィンドウが表示された場合、
   **ならば**: ウィンドウ上部左側に OS 標準の赤・黄・緑のトラフィックライトボタンが表示され、OS 標準位置にタイトル「Excel Grep」が表示される。
2. **前提**: Windows 環境でアプリケーションを起動する。
   **もし**: ウィンドウが表示された場合、
   **ならば**: ウィンドウ上部右側に OS 標準の最小化・最大化・閉じるボタンが表示され、OS 標準位置にタイトル「Excel Grep」が表示される。
3. **前提**: アプリケーションが表示されている。
   **もし**: タイトルバー領域をドラッグした場合、
   **ならば**: スムーズにウィンドウが追従して移動し、ダブルクリックした場合は OS 標準の動作（最大化またはズーム）が実行される。
4. **前提**: アプリケーション固有の補助情報（エンジン名やバージョン等）の表示を確認する。
   **もし**: 画面全体を表示した場合、
   **ならば**: タイトルバーのネイティブ化に伴い、補助情報は画面内（ヘッダーまたはステータスバー）の視認性を損なわない適切な領域に配置されて表示される。

### ユーザーストーリー 2 - macOS におけるファイルマネージャー連携（Finder 選択表示） (優先度: P2)

ユーザーは、プレビュー領域などから「フォルダを開く」操作を行った際、macOS では Finder が起動して該当ファイルが選択・ハイライトされた状態で表示される（Windows のエクスプローラー選択表示と同等の機能）。

**この優先度である理由**: 検索で見つかったファイルの保存場所を素早く確認・整理する上で、単に親フォルダを開くだけでなく該当ファイルを直接ハイライト表示できることがユーザーの作業効率を大きく高めるため。

**独立テスト方法**: macOS 環境で検索結果のプレビューヘッダーにある「フォルダを開く」ボタンをクリックし、Finder が前面に開き、対象ファイルがハイライトされた状態で親フォルダが表示されることを確認する。

**受入シナリオ**:

1. **前提**: プレビューに対象ファイルが表示されている。
   **もし**: 「フォルダを開く」ボタンをクリックした場合、
   **ならば**: macOS 上で Finder が起動し、該当ファイルが選択・強調表示された状態でフォルダウィンドウが開く。
2. **前提**: 対象ファイルが存在しない（移動または削除された）場合。
   **もし**: 「フォルダを開く」ボタンをクリックした場合、
   **ならば**: ユーザーに対してファイルが見つからない旨の分かりやすいエラー通知が表示され、異常終了しない。

### ユーザーストーリー 3 - macOS における関連付けアプリの検出と起動 (優先度: P3)

ユーザーは、macOS 環境において `.xlsx` または `.xls` ファイルに関連付けられた既定アプリケーション（Microsoft Excel、Apple Numbers、LibreOffice 等）およびインストール済みの対応アプリ一覧を確認し、ワンクリック起動およびポップアップメニューからの選択起動を行うことができる（Windows 向けに実装された機能と同等の操作性を macOS でも提供）。

**この優先度である理由**: 表計算ファイル（.xlsx / .xls）の閲覧・編集において、プラットフォームが異なってもユーザーが使い慣れた好みのアプリケーションを自由に選択して起動できるようにするため。

**独立テスト方法**: macOS 上でプレビューヘッダーの起動ボタンを確認し、ツールチップに既定アプリ名が表示されること、メインボタン押下で既定アプリが起動すること、およびドロップダウンメニューからインストール済み対応アプリを選択して起動できることを確認する。

**受入シナリオ**:

1. **前提**: macOS 上に対象ファイルが表示されている。
   **もし**: 起動ボタンを確認した場合、
   **ならば**: ボタンのツールチップに現在 macOS で `.xlsx` / `.xls` の既定となっているアプリケーション名（例: 「Microsoft Excel で開く」「Numbers で開く」等）が表示される。
2. **前提**: 起動ボタンのメイン領域をクリックした場合。
   **もし**: ユーザーがクリックを実行した場合、
   **ならば**: macOS の既定アプリケーションが起動し、対象ファイルが開かれる。
3. **前提**: 起動ボタンのメニューボタン（▼）をクリックした場合。
   **もし**: メニューが開いた場合、
   **ならば**: システムにインストールされている対応アプリケーション（Microsoft Excel, Numbers, LibreOffice 等）が一覧表示され、選択したアプリで対象ファイルが直接起動する。
4. **前提**: ポップアップメニューの「別のプログラムを選択...」をクリックした場合。
   **もし**: macOS のアプリケーション選択ダイアログ（/Applications）で任意の .app を選択した場合、
   **ならば**: 選択されたアプリケーションで対象ファイルが起動する。ダイアログでキャンセルした場合は安全に処理を終了する。
5. **前提**: 特定の対応アプリがシステムに検出されない、または未登録の場合。
   **もし**: メイン起動ボタンをクリックした場合、
   **ならば**: OS 既定のハンドラを介して安全に対象ファイルが開かれる。

### ユーザーストーリー 4 - マルチプラットフォーム共通のパス操作・ドラッグ＆ドロップおよびキーボード操作 (優先度: P4)

ユーザーは、macOS の POSIX パス形式（`/Users/...`）および Windows のドライブレターパス形式（`C:\...`）の双方において、フォルダ選択、ファイルやフォルダのドラッグ＆ドロップ登録、パスのクリップボードコピーを直感的に行える。また、主要なキーボード操作（検索実行、キャンセル、各種ショートカット）を各プラットフォームの標準規則に沿って利用できる。

**この優先度である理由**: 基本的な入力・出力・操作作法が各 OS の標準に合致していることで、ユーザーがプラットフォームの違いを意識せずストレスなく利用できるようにするため。

**独立テスト方法**: macOS 上で Finder からフォルダをドラッグ＆ドロップして検索対象パスに設定できること、プレビューの「パスをコピー」で POSIX パスが取得できること、Enter や Escape などのキー操作が期待通り動作することを確認する。

**受入シナリオ**:

1. **前提**: macOS 上で Finder からフォルダ（またはファイル）をドラッグする。
   **もし**: 検索バーのフォルダ入力領域にドロップした場合、
   **ならば**: 正しいディレクトリパス（POSIX 形式）が入力欄に設定される。
2. **前提**: プレビューヘッダーの「パスをコピー」をクリックする。
   **もし**: クリップボードの内容を別の場所（Terminal やテキストエディタ）に貼り付けた場合、
   **ならば**: macOS 上でそのまま利用可能な正しいパス文字列が取得できる。
3. **前提**: 検索入力欄にキーワードを入力している。
   **もし**: Enter キーを押下した場合、
   **ならば**: 即座に検索が開始され、検索中に Escape キーを押下した場合は安全に中断される。
4. **前提**: macOS 上でテキスト入力欄（検索バーや結果フィルタ）またはウィンドウを操作している。
   **もし**: コピー (⌘C)、ペースト (⌘V)、全選択 (⌘A)、ウィンドウクローズ (⌘W)、アプリ終了 (⌘Q) などの標準ショートカットキーを入力した場合、
   **ならば**: macOS 標準アプリケーションメニューと連動して期待通りの編集・ウィンドウ・終了操作が即座に実行される。

### Edge Cases

- **対応アプリ未インストール環境**: macOS 上に Microsoft Excel や Numbers などの対応アプリが 1 つも存在しない場合、OS 既定のドキュメントハンドラへのフォールバックを行い、開けない場合は明確なエラーメッセージをユーザーに通知する。
- **ファイル名・パスの特殊文字とエンコーディング**: macOS 特有のパス文字（濁点・半濁点を含む UTF-8 NFD/NFC 形式、空白、記号など）を含むフォルダ・ファイルでも、検索、プレビュー、Finder での表示、外部アプリ起動が正常に動作する。
- **フルスクリーンおよびウィンドウリサイズ**: macOS のフルスクリーンモードへの切り替えやウィンドウの最大化・リサイズ時に、画面レイアウトの崩れや操作不能な領域が発生しない。
- **アクセス権限の制限**: macOS のプライバシー設定（フォルダアクセス権限など）により保護されたディレクトリを指定した場合、クラッシュすることなく権限エラーまたはアクセス不可の旨を適切に通知する。
- **高解像度（Retina）ディスプレイ**: macOS の Retina ディスプレイ環境において、文字やアイコンのボケ、描画の滲み、境界線の欠けが発生しない。
- **アプリケーション選択のキャンセルまたは非対応形式**: アプリケーション選択ダイアログでユーザーが「キャンセル」を押下した場合、または実行不可能なファイルが選ばれた場合は、エラーまたは安全な無処理とし、アプリケーションが異常終了しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、macOS および Windows 双方において OS 標準のネイティブウィンドウ装飾（Title Bar、Window Controls）を有効化し、フロントエンドの独自タイトルバーおよび制御ボタンを廃止して、OS 固有の標準ウィンドウ操作（最小化、最大化/ズーム、クローズ、ドラッグ移動）を提供しなければならない (MUST)。
- **FR-002**: システムは、旧タイトルバーに表示されていた補助情報（エンジン名やバージョン情報等）を画面内レイアウト（ステータスバー等）に再配置し、タイトルバー領域には OS 標準のタイトルのみを表示しなければならない (MUST)。
- **FR-003**: システムは、macOS 環境において「フォルダを開く」が要求された際、Finder を起動して該当ファイルをハイライト選択した状態で表示しなければならない (MUST)。
- **FR-004**: システムは、macOS 環境において `.xlsx` および `.xls` ファイルに関連付けられた既定アプリケーションを特定し、起動ボタンのツールチップおよびワンクリック起動で利用可能にしなければならない (MUST)。
- **FR-005**: システムは、macOS 環境においてインストール済みの代表的な表計算対応アプリケーション（Microsoft Excel、Apple Numbers、LibreOffice 等）を検出し、選択起動メニューに一覧表示しなければならない (MUST)。
- **FR-006**: システムは、ポップアップメニューから選択された任意の対応アプリケーションで対象ファイルを直接起動できることに加え、「別のプログラムを選択...」操作時に macOS ではアプリケーション選択ダイアログ（/Applications 基準）を表示して選択された .app でファイルを開かなければならない (MUST)。
- **FR-007**: システムは、macOS におけるドラッグ＆ドロップ操作からディレクトリパスを正確に抽出し、検索対象フォルダとして設定できなければならない (MUST)。
- **FR-008**: システムは、パスのクリップボードコピーにおいて、各 OS に適したパス形式（macOS では POSIX 形式、Windows では標準パス形式）を出力しなければならない (MUST)。
- **FR-009**: システムは、Windows 固有の既存機能（レジストリからの ProgID 取得、エクスプローラーでの選択表示等）の動作と互換性を損なうことなく、プラットフォーム別の実装を分離して維持しなければならない (MUST)。
- **FR-010**: システムは、macOS 環境において OS 標準のアプリケーションメニュー（アプリ情報、編集、ウィンドウ等）を有効化し、テキスト編集（⌘C, ⌘V, ⌘A, ⌘Z 等）およびウィンドウ・アプリ制御（⌘W, ⌘Q 等）の標準ショートカット操作を完全サポートしなければならない (MUST)。
- **FR-011**: システムは、プラットフォーム固有の機能実装をビルド時および実行時に適切に分離しつつ、双方の OS で同等の機能・同等の操作体験を提供しなければならない (MUST)。

### Key Entities *(include if feature involves data)*

- **Window Configuration**: ウィンドウのタイトル、ネイティブ装飾の有効化設定、初期サイズ、最小サイズなどのウィンドウ外観・挙動プロパティ。
- **Supported Application**: 各 OS 環境で検出された表計算対応アプリケーションの情報（一意識別子、表示名、実行可能パスまたはアプリバンドル識別子、既定アプリフラグ、アイコン種別ヒント）。
- **File Target**: 操作対象となる Excel ファイルの情報（ファイルパス、親フォルダパス、ファイル拡張子）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: macOS および Windows の双方において、OS 標準のウィンドウ操作（ドラッグ移動、リサイズ、最小化、最大化/ズーム、クローズ）が 100% 正常に機能すること。
- **SC-002**: macOS における「フォルダを開く」操作において、クリックから 1 秒以内に対象ファイルが Finder 上で選択された状態で表示されること。
- **SC-003**: macOS 上で利用可能な表計算アプリケーション（既定アプリを含む）が正確に検出され、ワンクリックで起動できること（起動成功率 100%）。
- **SC-004**: macOS および Windows の双方において、既存の検索機能（Grep、プレビュー、エクスポート）が同一の精度と速度で動作すること。
- **SC-005**: Windows 既存機能に対するリグレッション（機能退行）が 0 件であること。
- **SC-006**: 初めて操作する macOS ユーザーが、OS標準の作法通りに迷わずウィンドウ操作およびファイル操作を完了できること。
- **SC-007**: macOS 環境において、主要な編集・操作ショートカット（⌘C, ⌘V, ⌘A, ⌘Q, ⌘W）が入力欄およびアプリケーション全体で 100% 期待通りに応答すること。

## Assumptions

- 対象とする macOS 環境は現代的なバージョン（macOS 12 Monterey 以降）を想定する。
- macOS 環境における主な対象表計算アプリは Microsoft Excel, Apple Numbers, LibreOffice Calc を想定する（その他の対応アプリも可能な限り検出）。
- UI 上のレイアウト構造（検索バー、結果テーブル、プレビューペイン、ステータスバー）の基本構成は既存仕様を踏襲する。
- プラットフォーム別の機能分離はビルド時の条件コンパイルおよび実行時プラットフォーム判定により安全に行われ、各 OS で未サポートの API 呼び出しによるクラッシュが発生しないように設計される。
