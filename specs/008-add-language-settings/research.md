# 調査結果: 表示言語の自動選択と設定画面

## 端末言語の取得

- **決定**: 言語設定が `default` または未設定の場合、起動時と `default` 選択時に Tauri の OS 情報機能で端末の言語タグを取得し、先頭言語が `ja` なら日本語、それ以外と取得失敗時は英語にする。保存済みの `ja`・`en` は端末言語より優先する。
- **理由**: 仕様の対象は端末の優先言語である。`navigator.language` は WebView 側の優先言語で、端末設定と常に一致する保証がない。[Tauri OS 情報](https://v2.tauri.app/plugin/os-info/)は言語取得機能と `os:allow-locale` 権限を提供する。
- **検討した代替**: `navigator.language` のみを使う案は追加依存がないが、端末言語とのずれを検出できない。端末言語を独自の OS 別処理で読む案は保守範囲が増える。

## 言語設定の保存と失敗時の動作

- **決定**: 言語設定と有効な表示言語をルートの共有状態で保持し、選択した `default`・`ja`・`en` を WebView の `localStorage` に保存する。読み取り・書き込みと `localStorage` 自体へのアクセスを例外処理で囲む。保存失敗時は今回の起動中の選択を保ち、最後に保存できた設定、またはデフォルトへ次回戻る旨を現在の表示言語で通知する。
- **理由**: 保存する値は `default`・`ja`・`en` の一件のみ。既存の保存機能はなく、追加のストア機能は不要。[MDN の localStorage 資料](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)はアクセス時の `SecurityError` を記載している。
- **検討した代替**: Tauri Store を追加する案は今回の一設定には過剰。保存成功まで表示を戻す案は、明確化で選択された動作に反する。

## 表示文言と進捗

- **決定**: `src/constants/index.ts` に日英の文言を言語ごとの辞書として集約し、React の有効な表示言語から描画時に参照する。対象言語にキーがない場合はそのキーだけ英語辞書を参照する。検索条件と結果の状態を保持する `App` は言語切り替えで再マウントしない。トーストは翻訳済み文字列ではなく文言キーと差し込み値を保持する。進捗イベントは状態・件数・実ファイル名・エラーコードを送信し、文言を画面側で組み立てる。
- **理由**: 現在の `UI_MESSAGES` と `ABOUT_DIALOG_CONSTANTS` は日本語のみで、`StatusBar.tsx` と `useSearch.ts` にも日本語の組み立てがある。`ScanProgress.current_file` はファイル名と固定文言を兼用しており、表示中の言語変更で再翻訳できない。
- **検討した代替**: バックエンドに言語を渡して完成済みの進捗文字列を返す案は、検索中の言語変更に追随しにくい。汎用翻訳ライブラリは今回の二言語と既存の固定文言には不要。

## エラーと英語ログの境界

- **決定**: Tauri コマンドの利用者向け失敗は安定したエラーコードを返し、フロントエンドで選択言語の説明に変換する。Rust の内部エラーとアプリ作成のログ説明は英語にし、OS・外部ライブラリの生のエラーは画面の文言へ連結しない。検索進捗の失敗も同じコード体系を使う。
- **理由**: 現在の `Result<_, String>` は日本語の固定文言と外部エラーを結合し、各コンポーネントがそのままトーストに出す経路がある。Tauri はシリアライズ可能なエラー型を IPC の失敗として返せる。[Tauri コマンドのエラー処理](https://v2.tauri.app/develop/calling-rust/)参照。
- **検討した代替**: コマンドごとの汎用メッセージだけを表示する案は、正規表現エラーなど利用者が直せる原因を区別できない。完成済みの翻訳文字列を Rust から返す案は表示言語の状態を二重管理する。

## 出力ファイルと macOS メニュー

- **決定**: `ExportRequest` に有効な言語を含め、CSV と Excel の列見出し、一致種別、シート名を同一言語で出力する。macOS のアプリ作成メニューは起動後の言語確定時と切り替え時に更新し、独自項目と Tauri の定義済み項目に日英のラベルを渡す。
- **理由**: 現在の出力見出しと macOS の独自 About 項目は日本語固定。Tauri の定義済みメニュー項目は表示テキストの指定を受け付け、アプリ全体のメニューを更新できる。[Tauri の定義済みメニュー項目](https://docs.rs/tauri/2.11.6/tauri/menu/struct.PredefinedMenuItem.html)、[アプリメニュー更新](https://docs.rs/tauri/2.11.6/tauri/struct.AppHandle.html)参照。
- **検討した代替**: 出力ファイルを常に英語にする案は仕様の出力見出し要件を満たさない。OS が生成するダイアログと第三者ライセンス本文は原文のままとする。

## 検証手段

- **決定**: デフォルトの言語判定、英語辞書の必須キー網羅、対象言語のキー欠落時の英語フォールバック、保存失敗時の状態を単体テストで確認する。変更する React コンポーネントとフックには Vitest と jsdom を用い、描画・操作・通知・状態維持を検証する。Rust は進捗・エラーコード・出力見出しの単体テストを追加する。画面での設定切り替えと再起動は `quickstart.md` に実機手順として記録する。
- **理由**: 純粋な言語ロジックだけのテストでは、変更する UI モジュールに対応する単体テストを作成する憲章要件を満たせない。既存の Vite 構成に Vitest と jsdom を追加し、React の操作も検証する。
- **検討した代替**: 実機確認だけに頼る案では、設定画面と通知の回帰を単体テストで検出できない。追加の UI テスト用ヘルパー群は導入せず、React の標準テスト API を使用する。
