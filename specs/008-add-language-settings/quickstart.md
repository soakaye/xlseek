# 動作確認ガイド: 表示言語の自動選択と設定画面

このガイドは実装後の確認手順である。期待するデータと境界は [データモデル](data-model.md) と [契約](contracts/localization-contract.md) を参照する。

## 準備

1. Node.js 22.18 以降を用意し、リポジトリのルートで `npm install` を実行する。
2. `npm run tauri dev` でアプリを起動する。
3. 検索の確認には `tests/fixtures/sample_report.xlsx` を含むフォルダを使う。
4. 初回起動の確認前には、開発ツールで `localStorage.removeItem('exlgrep.language')` を実行してアプリを再起動する。保存済みの `ja`・`en` は端末言語より優先され、`default` は端末言語に従う。

## 自動確認

```bash
npm test
npm run lint
npm run build
```

`src-tauri` で以下を実行する。

```bash
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

期待結果: すべて終了コード0、リント警告0件。デフォルトの言語判定、英語辞書のキー網羅、対象言語の文言欠落時の英語フォールバック、保存失敗時の状態、変更した React コンポーネント・フック、Rust のエラーコード・進捗・出力ラベルのテストが通る。

## 画面での確認

1. 端末の優先言語を日本語にして保存済み設定なしで起動する。検索画面、About、設定、通知、エラー、macOS ではアプリメニューが日本語になる。
2. 端末の優先言語を英語または日本語以外にして保存済み設定なしで起動する。同じ箇所が英語になる。
3. ステータスバーから設定画面を開き、30秒以内に表示言語を切り替えられることを計測する。「デフォルト」または「Default」、「日本語」、「English」を相互に選ぶ。選択後1秒以内に画面、開いている通知、進捗、ダイアログ、アプリメニューの文言が変わり、検索語、検索結果、選択中のセルは維持される。Esc と閉じるボタン、キーボード操作も確認する。
4. 「デフォルト」を保存し、端末言語を変えてアプリを再起動する。表示言語が端末言語に追随することを確認する。日本語または英語を保存した場合は端末言語を変更しても選択言語が維持される。
5. ファイルが見つからない場合と不正な正規表現で検索し、利用者への説明は表示言語に合い、外部由来の生エラーは表示されないことを確認する。
6. 両言語で同じ結果を CSV と Excel に出力する。列見出し、一致種別、Excel シート名が選択言語になり、ファイル名・シート名・セル値は元のまま残る。
7. 日本語表示と英語表示で代表的な操作とエラーを発生させ、アプリ自身のログ説明とエラー理由が英語であることを確認する。検索語とセル内容がログに出ないことも確認する。

## 異常系

- 保存処理を失敗させる単体テストで、今回の設定と表示言語は選択に従い、通知は現在の表示言語、保存済み設定は変更なしと確認する。再起動後は最後に保存できた設定、未保存ならデフォルトを使う。
- 保存済み値を未対応の値にして再起動し、端末言語による自動選択に戻ることを確認する。
- 端末言語の取得が失敗した場合は英語で利用を継続できることを確認する。
- 対象言語の辞書から一つの文言を欠落させた単体テストで、その文言だけ英語になり、ほかの文言と設定は変わらないことを確認する。

## UI 試作の同期

設定画面の構造、スタイル、言語選択肢を `design/mainui/index.html` でも確認する。実アプリと並べて主要な表示差がないことを確認する。
