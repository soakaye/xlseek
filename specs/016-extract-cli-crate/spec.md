# Feature Specification: CLIプログラムソースのTauriディレクトリからの分離・独立化 (Separate CLI Program Source from Tauri Directory)

**Feature Branch**: `016-extract-cli-crate`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "独立したCLIプログラムソースがtauriディレクトリ @src-tauri 内に有るのは不適切。改善する。"

## Clarifications

### Session 2026-09-29
- Q: CLIプログラムの分離にあたり、検索やエクスポートなどの共通ロジックを独立した共有クレート（例: crates/core）として抽出し、CLI（crates/cli）とGUI（src-tauri）の双方がそれに依存するマルチクレート構成にしますか？ → A: 共通ロジックを crates/core、CLIを crates/cli に抽出し、src-tauri と併せて3クレート構成とする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 独立したCLIパッケージとしてのビルドと実行 (Priority: P1)

開発者および利用者は、Tauriデスクトップ環境（GUIランタイムやGUIプラグイン）に依存することなく、独立したCLIパッケージ（`crates/cli`）としてソースコードからCLIツールを直接ビルド、テスト、実行できる。

**Why this priority**: CLIツールがGUIフレームワーク用ディレクトリ（`src-tauri`）内に組み込まれている状態を解消し、CLI単独での迅速なビルド・開発・配布を可能にするため。

**Independent Test**: GUI環境のビルドを行うことなく、CLIパッケージ単独でビルドおよび単体・統合テストを実行し、すべてのテストが正常に完了することを確認する。

**Acceptance Scenarios**:

1. **Given** プロジェクトのリポジトリが存在するとき、**When** 利用者がCLIパッケージ（`crates/cli`）のみをターゲットとしてビルド・実行したとき、**Then** GUI用ビルド手順やGUI依存ライブラリを介さずに、スタンドアローンのCLI実行ファイルが生成される。
2. **Given** 生成されたCLI実行ファイルが存在するとき、**When** 利用者がコマンドライン引数（ヘルプ表示、検索実行、結果出力等）を指定して実行したとき、**Then** 既存機能仕様（014/015）と同等の結果が得られる。

---

### User Story 2 - ディレクトリ構成の明確な分離と責務の明確化 (Priority: P1)

開発者は、`src-tauri` 内にCLI固有のコード（CLI専用バイナリエントリポイント、コマンドライン引数解析、CLI用出力フォーマッタ、CLI用テスト）が混在しない、関心の分離が徹底されたディレクトリ構成（`crates/core`, `crates/cli`, `src-tauri`）でコードベースを保守・拡張できる。

**Why this priority**: プロジェクトの長期的な保守性を高め、デスクトップGUIの変更がCLIに不用意な影響を与えず、逆にCLIの変更がGUIビルドに影響を与えない独立性を確保するため。

**Independent Test**: `src-tauri` 配下にCLI固有のソースファイルやバイナリ定義が存在しないことを検証し、各ディレクトリの責務が単一であることを確認する。

**Acceptance Scenarios**:

1. **Given** ソースコードツリーを検査したとき、**When** `src-tauri` ディレクトリ内を確認したとき、**Then** Tauriデスクトップアプリケーション専用の構成およびソースコードのみが存在し、CLI専用のエントリポイントやCLI専用モジュールが含まれていない。
2. **Given** CLI関連のソースコードを確認したとき、**When** その配置先を確認したとき、**Then** `src-tauri` 外の独立した `crates/cli` 配下に集約されており、共通ロジックは `crates/core` に抽出されている。

---

### User Story 3 - 既存CLI機能およびGUI機能の完全な互換性維持 (Priority: P1)

利用者は、ソースコード配置の分離改善後も、従来のすべてのCLI機能（各種検索オプション、ショートオプション、CSV/Excel出力、文字エンコーディング、終了ステータス）およびGUIデスクトップアプリケーション機能を同一の動作として利用し続けることができる。

**Why this priority**: ディレクトリ構成の整理やパッケージ分離に伴うリグレッション（仕様変更や機能破損）を防止し、利用者への影響を与えないため。

**Independent Test**: 既存のCLI統合テストおよびGUIの各機能テストを実行し、すべての受け入れ条件が変更前と同一の結果となることを確認する。

**Acceptance Scenarios**:

1. **Given** 移行前のCLIコマンドライン引数指定があるとき、**When** 分離後のCLI実行ファイルで同一の引数を指定して実行したとき、**Then** 検索結果、出力ファイル形式、および終了コードが完全に一致する。
2. **Given** GUIデスクトップアプリケーションを起動したとき、**When** 検索やエクスポートなどの通常操作を実行したとき、**Then** コアロジックのクレート分離後もCLI分離の影響を受けることなく正常に動作する。

---

### Edge Cases

- **共通コア機能（検索・解析・出力）の共有**:
  GUIとCLIの双方が使用するコアロジック（Excel解析、並列走査、エクスポート処理、データモデル、定数）が二重管理にならず、`crates/core` クレートから単一ソースとして安全に共有されること。
- **CI/ワークスペース全体のビルドとテスト**:
  ルートワークスペースから全パッケージの一括ビルド・テストを実行した場合と、個別パッケージ（`crates/cli` や `src-tauri`）を指定して実行した場合の双方が正常に成功すること。
- **プラットフォーム固有の依存性**:
  Windows/macOS等のOS固有機能（レジストリ参照、ファイル関連付け等）がGUI側にある場合、CLI側が不要なGUI依存を引き込まないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、CLIツールの実行可能バイナリ定義、コマンドライン引数解析モジュール、CLI出力制御モジュール、およびCLI統合テストを、`src-tauri` ディレクトリ外の独立したパッケージディレクトリ（`crates/cli`）配下に配置しなければならない (MUST)。
- **FR-002**: `src-tauri` ディレクトリ配下には、デスクトップGUIアプリケーションに固有のソースコードおよび設定のみを配置し、独立CLI専用のソースコードやバイナリ定義を含めてはならない (MUST NOT)。
- **FR-003**: 検索エンジン、Excelファイル解析、エクスポートロジック、データモデル、および共通定数定義などの共通ロジックは、独立した共有クレート `crates/core` として抽出・提供し、GUIパッケージ（`src-tauri`）とCLIパッケージ（`crates/cli`）の双方がこれを依存ライブラリとして再利用しなければならない (MUST)。
- **FR-004**: CLIパッケージ（`crates/cli`）は、Tauriのビルドスクリプト（`tauri-build`）やTauriプラグイン（ダイアログ、シェル等のGUI拡張）に依存することなく、単独でコンパイル・テスト実行可能でなければならない (MUST)。
- **FR-005**: 分離後のCLIパッケージは、既存の機能仕様（014-cli-search-export および 015-cli-short-options）で定義されたすべてのコマンドラインオプション、ショートオプション、出力機能、終了ステータス規則と完全な互換性を保持しなければならない (MUST)。
- **FR-006**: CLIプログラムおよび共通ロジックの分離作業は、既存のGUIデスクトップアプリケーション（`src-tauri`）の機能、UI表示、ビルド手順、およびテストに対して一切の破壊的影響を与えてはならない (MUST NOT)。
- **FR-007**: すべての新規・移動されたソースコードおよび設定ファイルは、プロジェクト憲章の全原則（原則 I: 日本語品質、原則 II: 定数一元化、原則 III: 4要素ヘッダコメント、原則 IV: モジュール分割・Clippy/fmt準拠、原則 V: エラーハンドリング・テスト検証）を厳格に遵守しなければならない (MUST)。

### Key Entities

- **CLI Package (`crates/cli`)**: CLI実行可能バイナリ（`exlgrep-cli`）を提供する独立したパッケージ。コマンドライン引数の解析、実行制御、結果表示・保存、終了コード管理を担う。
- **Shared Core Package (`crates/core`)**: 検索エンジン（セル、コメント、図形内テキスト）、ファイル走査、Excel/CSVエクスポート、共通データモデル、およびコア定数定義など、GUIとCLIで共通利用される中核機能を提供するライブラリパッケージ。
- **Tauri GUI Package (`src-tauri`)**: Tauriデスクトップアプリケーション専用のバックエンドパッケージ。ウィンドウ管理、Tauri IPCコマンド、システムメニュー、UI向けイベント通知、GUIプラグイン連携を担い、`crates/core` に依存する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `src-tauri` 配下にCLI専用のバイナリエントリポイント（`src/bin/exlgrep-cli.rs`）およびCLI専用ソースモジュール（`src/cli/` 等）が残存件数 0 件となること。
- **SC-002**: CLIパッケージ（`crates/cli`）単独でのビルドおよび全単体・統合テストが、GUI関連依存を含まずにエラーおよび警告 0 件で成功すること。
- **SC-003**: 既存のCLI機能仕様（014/015）の全受け入れシナリオおよびテスト項目が 100% 継続して合格すること。
- **SC-004**: GUIデスクトップパッケージ（`src-tauri`）のビルドおよびテストがリグレッションなく 100% 継続して合格すること。
- **SC-005**: ワークスペース全体の品質検証コマンド（`cargo clippy`、`cargo fmt`、`cargo test`、`npm run build`）がすべてエラー 0 件・警告 0 件でパスすること。

## Assumptions

- リポジトリのビルドシステムとして Rust の Cargo ワークスペース構成（`[workspace]`）を拡張し、`crates/core`, `crates/cli`, `src-tauri` の3メンバー構成とする。
- 分離後のCLI実行ファイル名（バイナリ名）は既存利用者の利便性を考慮し、引き続き `exlgrep-cli` とする。
- 憲章 原則 II（定数の外部抽出）に基づき、各クレートはそれぞれの責務に応じた定数モジュール（`constants.rs`）を保持してマジックナンバーやハードコード文字列を排除する。
