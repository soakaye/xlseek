# Bug Assessment: 入力欄から離れても検索履歴・パス候補が残る

- **Slug**: history-popup-focus-loss
- **Created**: 2026-09-27
- **Source**: ユーザーの報告文
- **Verdict**: valid
- **Severity**: medium

## Report (verbatim or summarized)

> 検索文字列や検索パスおよびそれぞれの履歴からフォーカスが失われた時に履歴表示を消去しておらず画面に残ったままになっている。

## Symptom

検索文字列または検索パスの履歴・補完候補を表示した後、別の画面要素へフォーカスを移しても一覧が残る。入力欄とその履歴・候補の操作領域からフォーカスが外れた時点で一覧が閉じることが期待される。

## Reproduction

1. 検索文字列または検索パスの履歴ボタンを押して一覧を開く。検索パスでは、候補があるパスを入力して補完一覧を開く操作でもよい。
2. 一覧の項目を選ばず、別の入力欄や検索ボタンへフォーカスを移す。
3. 一覧が閉じずに残る。パス補完の要求中にフォーカスを外すと、応答後に候補が表示される可能性もある。

コード上の発生条件を確認した。実アプリでの再現操作は未実施。

## Suspected Code Paths

- `src/components/search/SearchBar.tsx:79-106` — 一覧を `openList` で管理し、パス補完の非同期応答で `directory` にする。応答時にフォーカス状態を確認しない。
- `src/components/search/SearchBar.tsx:108-156` — `closeList` は項目選択・Escape で呼ばれ、履歴ボタンの再操作でも一覧が閉じる。パス入力変更でも一覧を閉じるが、フォーカス離脱では閉じない。
- `src/components/search/SearchBar.tsx:349-445` — 両入力欄、履歴ボタン、一覧にフォーカス離脱時のハンドラがない。
- `design/mainui/index.html:8514-8532,8667-8668` — 試作画面も一覧表示・項目選択による非表示のみで、同じ挙動になる。
- `tests/search-history-ui.test.tsx:32-130` — 選択・候補切替・古い入力への応答は検証するが、フォーカス離脱は検証しない。

## Root Cause Hypothesis

**確信度: high。** 一覧表示は `openList` が非 `null` の間続くが、入力欄またはその履歴・候補からフォーカスが外れた時に `closeList` を呼ぶ経路がない。パス補完は入力文字列と要求番号だけで応答を採用するため、フォーカスを失った後の応答でも一覧を再表示し得る。

## Proposed Remediation

**Preferred**: `SearchBar.tsx` で各入力欄と履歴ボタン・一覧を一つのフォーカス領域として扱い、領域外へのフォーカス移動時に対応する一覧を閉じる。領域内のボタンや項目へ移る場合は閉じず、クリックとキーボードによる選択を保つ。領域外へ移った時点で進行中の補完応答を無効化し、入力欄にフォーカスがない状態では候補を開かない。試作画面にも同じ挙動を反映する。

**Files likely to change**:

- `src/components/search/SearchBar.tsx`
- `tests/search-history-ui.test.tsx`
- `design/mainui/index.html`

**Tests to add or update**:

- 検索文字列・検索パスの履歴とパス候補が、別の欄・検索ボタンへフォーカスを移すと閉じること。
- 入力欄から同じ領域の履歴ボタン・候補項目へ移る間は一覧を選択できること。
- フォーカス離脱後に遅れて返った補完応答が一覧を再表示しないこと。
- Tab、マウスによる移動と IME 入力で、選択・検索が誤発火しないこと。

## Risks & Considerations

- 入力欄の `onBlur` だけで即時に閉じると、履歴ボタンや項目を押す前に一覧が消える恐れがある。移動先が同じ操作領域内か判定する必要がある。
- フォーカスの移らない領域へのマウスクリックも考慮すると、領域外クリックの扱いを確認する必要がある。
- バックエンド API、保存データ、検索結果には変更が不要。
